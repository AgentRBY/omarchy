# IA

Omarchy trata a los agentes de IA para código como ciudadanos de primera clase, pero no elige un favorito por ti. En su lugar, cada CLI importante de agente para código viene precableada como un lanzador de carga diferida. Los lanzadores son stubs diminutos administrados por [mise](https://mise.jdx.dev/) en `~/.local/bin/`, así que no se descarga nada hasta la primera vez que de verdad ejecutas uno. Hermes es la excepción: no hay ningún stub para él, y elegirlo instala Hermes Desktop, como explica _Aplicaciones de escritorio_ más abajo. Invoca cualquiera de estos y autentícate cuando se te pida:

| Comando    | Agente                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) de xAI                        |
| `pi`       | [Pi de Mario Zechner](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), el arnés de OpenRouter |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), el agente de Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai), el agente para código de Meta           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` es el raro del grupo: ejecuta los demás arneses contra todo el catálogo de modelos de OpenRouter, así que `ori claude`, `ori codex` u `ori opencode` inician esos agentes con el modelo que les indiques, y `ori code` es el agente propio de Ori.

Para envolver una CLI adicional de la misma manera, ejecuta `omarchy-mise-install <package> [command-name]`. Los stubs se mantienen al día junto con todo lo demás que administra mise cuando ejecutas `omarchy update` (o el alias `mup`).

`grok` se instala a través del paquete propio `grok` de mise, igual que `claude` y `codex`. Ejecuta `grok`, o elígelo en _Configurar > Predeterminados > Agente_. Sáltate el instalador `curl | bash` de x.ai. Ese camino pone una segunda copia en `~/.grok/bin`, la antepone en `PATH` y sobrescribe el envoltorio de Omarchy.

### El agente predeterminado

Elige tu agente predeterminado con `omarchy default agent <name>` o en _Configurar > Predeterminados > Agente_ en el menú de Omarchy (`Super + Space`). Si el agente aún no está instalado, al elegirlo se instala primero. Un Omarchy nuevo te invitará a tomar esta decisión con una notificación única.

Elegir Claude también intenta configurar su extensión de navegador para Chromium, Chrome, Brave, Brave Origin y Edge. La configuración de la extensión aplica a todos los usuarios y puede pedir tu contraseña del sistema; cancelar o que la instalación de la extensión falle igual selecciona y abre Claude. Reinicia tu navegador, activa la extensión si se te pide e inicia sesión en Claude para terminar de conectarla. Ejecuta `/chrome` en Claude para verificar la conexión. Firefox y Zen no admiten esta extensión. Si Claude ya era tu predeterminado antes de que se agregara esta configuración, vuelve a seleccionarlo para instalar la extensión.

[Muse Code](https://dev.meta.ai) — el `muse` de Meta — usa un stub de mise preinstalado como los demás agentes. Al elegirlo como predeterminado se instala el lanzador oficial de Meta a través del backend HTTP de mise. El lanzador verifica y actualiza el binario nativo para tu máquina.

Una vez que elegiste, `Super + Shift + Ctrl + A` abre el agente predeterminado en una ventana de terminal dedicada (o muestra el selector si aún no has elegido). También puedes abrirlo directo a una tarea con `omarchy agent prompt "Review this project"`. Los agentes abiertos así corren sin supervisión en sus respectivos modos de no detenerse a preguntar, ¡así que prepárate para que de verdad hagan cosas! Y como los agentes se niegan a recordar la confianza para tu directorio home, los lanzamientos desde `$HOME` empiezan en `~/Work` mejor.

También hay atajos de terminal: `a` ejecuta el agente predeterminado en línea en la terminal actual, mientras que `c`, `cx` y `cy` inician OpenCode, Claude Code y Codex directamente (también en sus modos de aprobación automática). Los cambios de tema también se sincronizan a los agentes: Claude Code, Pi, OpenCode y Hermes (una vez que Omarchy lo ha instalado) te siguen cuando cambias el tema de Omarchy.

### El panel de agentes

La barra superior tiene un icono de agentes. Antes de que hayas configurado un agente, su panel te guía para iniciar sesión en Claude, Codex o Grok, y el primero se convierte en tu agente predeterminado. Después de eso, el panel pone cada suscripción en una sola página: cada agente y cuenta con su plan, un medidor para cada uno de sus límites de sesión de 5 horas y semanales con el tiempo hasta que se restablece (pasa el cursor para el porcentaje exacto), o el saldo prepagado restante, bajo una línea que va rotando por lo que has usado en todos ellos, como los tokens de esta semana y tu modelo más usado. En _Make something_ ofrece prompts iniciales para un tema, plugin o app nuevos que le entregan la tarea a tu agente predeterminado. Las apps se construyen como las propias Hype, Monologue y Omacut de Omarchy, en C++ y Qt Quick, siguiendo la skill de agente omarchy-app, y el compilador y las piezas de Qt que necesitan ya vienen instalados. Claude Code, Codex, Grok y Fireworks están cubiertos desde el inicio.

Haz clic izquierdo en el icono de la barra para el panel, clic derecho para abrir tu agente predeterminado. Los registros de uso detrás de él se regeneran cada 15 minutos con `omarchy agent usage-update`, y el panel incluso puede fusionar el uso de tus otras máquinas mediante una carpeta sincronizada. Consulta el README en `$OMARCHY_PATH/shell/plugins/agents/` para todos los ajustes.

### Varias suscripciones

Si pagas por más de un plan de Claude, Codex o Grok — un Max personal y uno del trabajo, digamos — Omarchy puede mantenerlos todos con sesión iniciada y moverse entre ellos. Agrega una suscripción con el + en el panel de agentes, que te guía ahí mismo, o con `omarchy agent account add claude Work` (o `codex`, o `grok`). Instala la CLI si falta. La primera cuenta de un proveedor inicia sesión en tu navegador normal, justo donde la CLI siempre busca. Cada una después de esa inicia sesión en una ventana privada, para que la cuenta en la que tu navegador ya tiene sesión no se tome por error; inicia sesión ahí con la cuenta que estás agregando y cierra antes cualquier ventana privada que ya tuvieras abierta. Nunca cierres sesión en la CLI para hacer esto: cerrar sesión revoca el inicio guardado, y esa cuenta tendría que agregarse otra vez.

Una cuenta por proveedor está activa, y cada sesión nueva empieza como ella: `cx`, `cy`, un simple `claude`, `codex` o `grok`, cualquier cosa abierta con `omarchy agent`, y scripts o editores que encuentren la CLI en `PATH`. Cambia con `omarchy agent account use work` (y de vuelta con `omarchy agent account use main`), o en el panel presionando el número de una cuenta y luego `Enter` (o haciendo clic en su botón Use). Las sesiones que ya están corriendo se quedan en la cuenta con la que empezaron. El historial de conversaciones, los ajustes, las skills y los plugins se comparten entre cuentas, así que `claude --continue` en la misma carpeta retoma donde te quedaste con la cuenta nueva.

Con más de una cuenta, el panel muestra los límites de cada cuenta lado a lado, con la activa marcada. Por defecto, Omarchy te avisa cuando la cuenta activa pasa el 95% de un límite, y al hacer clic en la notificación cambia a la cuenta con más margen. Pasa el cursor sobre la línea de una cuenta en el panel y haz clic en el Autoswitch que aparece junto a Use (o presiona `m`), o ejecuta `omarchy agent account mode auto`, para que cambie solo; mientras está activo, Autoswitch toma el lugar de Use, y al hacer clic otra vez regresa a avisar. Agrega un número para cambiar el umbral, como en `omarchy agent account mode auto 90`. Si todas las cuentas están sobre el umbral, te enterarás una sola vez, junto con cuál cuenta se libera primero. Mientras una cuenta activa está a 15 puntos de su umbral (80% con el valor predeterminado), sus límites se revisan cada tres minutos en lugar de cada 15.

`omarchy agent account list` muestra cada cuenta y sus límites más recientes, `omarchy agent account remove work` olvida una, y `omarchy agent account rename primary Hey` renombra una (o haz clic en el nombre de una cuenta en el panel). Estos comandos funcionan sobre las cuentas de tu agente predeterminado; para llegar al otro proveedor, nómbralo primero, como en `omarchy agent account use codex side`. El inicio de sesión que ya tenías en `~/.claude` o `~/.codex` es la cuenta _Main_ y se queda donde está. Una cuenta sin usar por más de unas ocho horas puede mostrar _Sign-in required_; haz clic para iniciar sesión otra vez con esa cuenta ahí mismo en el panel, o inicia una sesión en ella, lo cual renueva el inicio solo. Los servidores MCP que tenías cuando se agregó una cuenta vienen con ella, pero los que agregues después con `claude mcp add` solo llegan a la cuenta en la que los agregaste. Claude Desktop y las herramientas configuradas con una ruta absoluta a un binario CLI no siguen el cambio. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícito tiene prioridad sobre la cuenta seleccionada.

### Diagnóstico de fallos

Omarchy vigila systemd-coredump en busca de fallos de procesos. Cuando algo hace segfault, recibirás una notificación "Process crashed" — haz clic y el fallo se entrega a tu agente predeterminado junto con la skill diagnose-crash de Omarchy, que guía al agente para establecer los hechos desde el core dump y decidir si el fallo vale la pena reportarse upstream. También puedes ejecutarlo a mano contra cualquier PID de `coredumpctl list` con `omarchy agent crash <pid>`.

La vigilancia está activada por defecto. Desactívala en _Activar > Alternar > Captura de fallos_ (o con `omarchy toggle crash-capture`) y las notificaciones paran; `omarchy agent crash <pid>` sigue funcionando a mano.

Los fallos también se pueden silenciar programa por programa, que es lo que el diagnóstico te ofrece al final. `omarchy crash mute hyprland` detiene las notificaciones solo para ese programa, `omarchy crash mute hyprland off` las regresa, y `omarchy crash mute` por sí solo enumera lo que has silenciado. Acepta la ruta del binario tan contento como su nombre, así que `omarchy crash mute /usr/bin/hyprland` hace lo mismo. Entrecomilla un nombre con espacio, como en `omarchy crash mute 'Some App'`. Todo lo demás sigue avisando, y el programa silenciado sigue fallando — esto esconde el recordatorio, no arregla nada.

### Aplicaciones de escritorio

El menú _Instalar > IA_ también incluye algunas apps gráficas de IA: la app de escritorio de ChatGPT, la app de escritorio de Claude (la beta de Linux de Anthropic, con pestañas Chat, Cowork y Claude Code), Grok Bot para chatear con los modelos de xAI, Hermes Desktop, OpenClaw y la app de escritorio de Perplexity. Grok Bot es la app de chat de escritorio. El agente para código es el comando `grok`.

Hermes Desktop es la que hay que conocer, porque una máquina tiene un solo Hermes, y es el de la app: Hermes solo se instala siempre a través de la app, y el comando `hermes` que ejecuta el agente predeterminado es el de la app. Elegir Hermes como agente predeterminado instala lo mismo que la entrada _Instalar > IA_: el paquete y un runtime de Hermes bajo `~/.hermes` configurado por el propio instalador de Hermes, que tarda unos minutos la primera vez. Ese runtime es el único Hermes que usan el comando de terminal `hermes`, el agente predeterminado y la app, y se actualiza solo con `hermes update` en lugar de esperar una versión de Omarchy. Al instalarlo también le entrega a Hermes el tema de Omarchy como una skin llamada `omarchy`, que cada superficie de Hermes sigue al cambiar de temas; elige otra en los ajustes de Apariencia de Hermes o con `/skin` si prefieres que no lo haga, y Omarchy deja esa elección en paz. Quitar la app en _Quitar > IA_ cierra Hermes primero, gateway incluido, se lleva ese runtime con él y conserva tus chats, memorias y las skills que Hermes escribió para sí mismo a menos que digas lo contrario: pregunta, con «no» por defecto, si esos datos y tus ajustes de conexión también deben irse.

La experiencia de escritorio de OpenClaw es su Control UI, que se abre como una app web respaldada por su propio gateway local. OpenClaw vive en `~/.openclaw` y se actualiza solo: usa el botón "Update Gateway" de la Control UI o ejecuta `openclaw update`, y el gateway se reinicia con la versión nueva. Omarchy solo elige la versión con la que arranca una instalación nueva. Quitar OpenClaw en _Quitar > IA_ se lleva el servicio de gateway y la app con él y luego pregunta si `~/.openclaw` también debe irse, ya que ahí están tus chats y credenciales junto a OpenClaw mismo y los runtimes de plugins que descarga; el valor predeterminado lo conserva, e instalar OpenClaw otra vez lo retoma.

### LLM locales

Omarchy recomienda dos formas de ejecutar modelos LLM locales: LM Studio y Ollama. LM Studio ofrece una interfaz GUI para encontrar modelos de pesos abiertos, instalarlos y ejecutarlos. Es una gran manera de arrancar fácil. Ollama ofrece una CLI para hacer algo parecido. Pero si eres nuevo en los modelos locales, yo empezaría con LM Studio. Puedes instalar cualquiera de los dos en _Instalar > IA_ en el menú de Omarchy.

### La skill de Omarchy

Las skills de agente ayudan a la IA a usar herramientas específicas de una forma específica, y Omarchy incluye una skill predeterminada para ajustar el sistema a tu medida. Como retocar tu configuración de Hyprland, ajustar la barra o incluso crear un tema nuevo desde cero. Está enlazada con symlinks en los directorios de skills de Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` y cada `~/.hermes/profiles/*/skills`) y la ubicación genérica `~/.agents/skills`, así que la mayoría de los arneses la toman automáticamente.

Pero debes tratar esta skill como experimental. Distintos modelos la usarán con distinto efecto. Lo mejor es correr primero en modo plan, para que tengas una idea de lo que el agente querría cambiar. Y luego estar listo para revertir cambios o incluso invocar `omarchy reinstall configs`, si el agente hace un desastre con todo.
