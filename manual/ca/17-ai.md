# IA

Omarchy tracta els agents de codificació amb IA com a ciutadans de primera classe, però no us tria un preferit. En canvi, cada CLI d'agent de codificació important ve precablejat com a llançador de càrrega diferida. Els llançadors són petits stubs gestionats per [mise](https://mise.jdx.dev/) a `~/.local/bin/`, de manera que res no es baixa fins que realment n'executeu un per primera vegada. Hermes és l'excepció: no se'n fa cap stub, i triar-lo instal·la Hermes Desktop, com explica _Aplicacions d'escriptori_ més avall. Invoqueu-ne qualsevol i autentiqueu-vos quan us ho demani:

| Ordre    | Agent                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) de xAI                        |
| `pi`       | [Mario Zechner's Pi](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), l'arnès d'OpenRouter |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), l'agent de Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai), l'agent de codificació de Meta           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` és el diferent: executa els altres arnesos contra tot el catàleg de models d'OpenRouter, de manera que `ori claude`, `ori codex` o `ori opencode` inicien aquests agents amb el model que els hi apunteu, i `ori code` és l'agent propi d'Ori.

Per envoltar una CLI addicional de la mateixa manera, executeu `omarchy-mise-install <package> [command-name]`. Els stubs es mantenen al dia juntament amb tot el que mise gestiona quan executeu `omarchy update` (o l'àlies `mup`).

`grok` s'instal·la mitjançant el paquet `grok` propi de mise, de la mateixa manera que `claude` i `codex`. Executeu `grok`, o trieu-lo a _Configuració > Per defecte > Agent_. Ometeu l'instal·lador `curl | bash` de x.ai. Aquest camí posa una segona còpia a `~/.grok/bin`, la anteposa al `PATH` i sobreescriu l'embolcall d'Omarchy.

### L'agent per defecte

Trieu el vostre agent per defecte amb `omarchy default agent <name>` o a _Configuració > Per defecte > Agent_ al menú d'Omarchy (`Super + Space`). Si l'agent encara no està instal·lat, triar-lo l'instal·la primer. Un Omarchy nou us convidarà a fer aquesta elecció amb una notificació única.

Triar Claude també intenta configurar la seva extensió de navegador per a Chromium, Chrome, Brave, Brave Origin i Edge. La configuració de l'extensió s'aplica a tots els usuaris i pot demanar la contrasenya del sistema; cancel·lar o una instal·lació d'extensió fallida igualment selecciona i llança Claude. Reinicieu el navegador, activeu l'extensió si us ho demana i inicieu sessió a Claude per acabar de connectar-la. Executeu `/chrome` a Claude per comprovar la connexió. Firefox i Zen no admeten aquesta extensió. Si Claude ja era el vostre predeterminat abans que s'afegís aquesta configuració, torneu-lo a seleccionar per instal·lar l'extensió.

[Muse Code](https://dev.meta.ai) — el `muse` de Meta — fa servir un stub de mise preinstal·lat com els altres agents. Triar-lo com a predeterminat instal·la el llançador oficial de Meta mitjançant el backend HTTP de mise. El llançador verifica i actualitza el binari natiu per a la vostra màquina.

Un cop heu triat, `Super + Shift + Ctrl + A` llança l'agent per defecte en una finestra de terminal dedicada (o obre el selector si encara no heu triat). També el podeu llançar directament en una tasca amb `omarchy agent prompt "Review this project"`. Els agents llançats així funcionen sense supervisió en els seus respectius modes de no aturar-se a preguntar, així que estigueu preparats perquè realment facin coses! I com que els agents es neguen a recordar la confiança per al vostre directori personal, els llançaments des de `$HOME` comencen a `~/Work`.

També hi ha dreceres de terminal: `a` executa l'agent per defecte en línia al terminal actual, mentre que `c`, `cx` i `cy` inicien OpenCode, Claude Code i Codex directament (també en els seus modes d'aprovació automàtica). Els canvis de tema també se sincronitzen amb els agents: Claude Code, Pi, OpenCode i Hermes (un cop Omarchy l'ha instal·lat) segueixen el canvi quan canvieu el tema d'Omarchy.

### El panell d'agents

La barra superior té una icona d'agents. Abans d'haver configurat un agent, el seu panell us guia per iniciar sessió a Claude, Codex o Grok, i el primer esdevé el vostre agent per defecte. Després d'això, el panell posa cada subscripció en una pàgina: cada agent i compte amb el seu pla, un mesurador per a cadascun dels seus límits de sessió de 5 hores i setmanals amb el temps fins que es restableixi (passeu el cursor per sobre per al percentatge exacte), o el saldo prepagat restant, sota una línia que recorre el que heu fet servir en tots ells, com els tokens d'aquesta setmana i el vostre model més utilitzat. A _Make something_ ofereix indicacions inicials per a un tema, un complement o una aplicació nous que lliuren la tasca al vostre agent per defecte. Les aplicacions es construeixen com es construeixen les pròpies Hype, Monologue i Omacut d'Omarchy, en C++ i Qt Quick, seguint la skill d'agent omarchy-app, i el compilador i les peces de Qt que necessiten ja vénen instal·lats. Claude Code, Codex, Grok i Fireworks estan coberts de sèrie.

Feu clic amb el botó esquerre a la icona de la barra per al panell, amb el botó dret per llançar l'agent per defecte. Els registres d'ús que hi ha al darrere es regeneren cada 15 minuts amb `omarchy agent usage-update`, i el panell fins i tot pot fusionar l'ús de les vostres altres màquines mitjançant una carpeta sincronitzada. Vegeu el README a `$OMARCHY_PATH/shell/plugins/agents/` per a tots els paràmetres.

### Diverses subscripcions

Si pagueu més d'un pla de Claude, Codex o Grok — un Max personal i un de feina, per exemple — Omarchy els pot mantenir tots amb sessió iniciada i moure's entre ells. Afegiu una subscripció amb el + del panell d'agents, que us hi guia allà mateix, o amb `omarchy agent account add claude Work` (o `codex`, o `grok`). Instal·la la CLI si falta. El primer compte d'un proveïdor inicia sessió mitjançant el vostre navegador normal, exactament on la CLI sempre mira. Cada un dels següents inicia sessió mitjançant una finestra privada, perquè el compte en què el navegador ja té sessió iniciada no es reculli per error; inicieu-hi sessió com el compte que esteu afegint, i tanqueu primer qualsevol finestra privada que ja tingueu oberta. No tanqueu mai la sessió de la CLI per fer això: tancar-la revoca l'inici de sessió desat, i aquest compte s'hauria d'afegir de nou.

Un compte per proveïdor és actiu, i cada sessió nova comença com a tal: `cx`, `cy`, un simple `claude`, `codex` o `grok`, qualsevol cosa llançada mitjançant `omarchy agent`, i scripts o editors que trobin la CLI al `PATH`. Canvieu amb `omarchy agent account use work` (i torneu amb `omarchy agent account use main`), o al panell prement el número d'un compte i després `Enter` (o fent clic al seu botó Use). Les sessions que ja s'estan executant es queden amb el compte amb què van començar. L'historial de converses, la configuració, les skills i els complements es comparteixen entre comptes, de manera que `claude --continue` a la mateixa carpeta reprèn on ho vau deixar amb el compte nou.

Amb més d'un compte, el panell mostra els límits de cada compte un al costat de l'altre, amb l'actiu marcat. Per defecte Omarchy us notifica quan el compte actiu supera el 95% d'un límit, i fer clic a la notificació canvia al compte amb més marge. Passeu el cursor sobre la línia d'un compte al panell i feu clic a l'Autoswitch que apareix al costat d'Use (o premeu `m`), o executeu `omarchy agent account mode auto`, perquè canviï sol; mentre és activat, Autoswitch ocupa el lloc d'Use, i tornar-hi a fer clic torna a notificar. Afegiu un número per canviar el llindar, com a `omarchy agent account mode auto 90`. Si tots els comptes superen el llindar, en sentireu a parlar una vegada, juntament amb quin compte s'allibera primer. Mentre un compte actiu és a 15 punts del seu llindar (80% per defecte), els seus límits es comproven cada tres minuts en lloc de cada 15.

`omarchy agent account list` mostra cada compte i els seus darrers límits, `omarchy agent account remove work` en oblida un, i `omarchy agent account rename primary Hey` en canvia el nom a un (o feu clic al nom d'un compte al panell). Aquestes ordres funcionen en els comptes del vostre agent per defecte; per arribar a l'altre proveïdor, anomeneu-lo primer, com a `omarchy agent account use codex side`. L'inici de sessió que ja teníeu a `~/.claude` o `~/.codex` és el compte _Main_ i es queda on és. Un compte que no es fa servir durant més d'unes vuit hores pot mostrar _Sign-in required_; feu-hi clic per iniciar sessió de nou en aquest compte directament al panell, o inicieu-hi una sessió, cosa que actualitza l'inici de sessió per si sola. Els servidors MCP que teníeu quan es va afegir un compte l'acompanyen, però els que afegiu després amb `claude mcp add` només arriben al compte on els heu afegit. Claude Desktop i les eines configurades amb una ruta absoluta a un binari CLI no segueixen el canvi. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícit té precedència sobre el compte seleccionat.

### Diagnòstic de fallades

Omarchy observa systemd-coredump per a fallades de processos. Quan alguna cosa fa un segfault, rebreu una notificació "Process crashed" — feu-hi clic i la fallada es lliura al vostre agent per defecte juntament amb la skill diagnose-crash d'Omarchy, que guia l'agent per establir els fets a partir del core dump i decidir si val la pena informar de la fallada a dalt. També el podeu executar a mà contra qualsevol PID de `coredumpctl list` amb `omarchy agent crash <pid>`.

L'observació és activada per defecte. Desactiveu-la a _Activa > Commuta > Captura de fallades_ (o amb `omarchy toggle crash-capture`) i les notificacions s'aturen; `omarchy agent crash <pid>` continua funcionant a mà.

Les fallades també es poden silenciar un programa cada vegada, que és el que el diagnòstic us ofereix al final. `omarchy crash mute hyprland` atura les notificacions només per a aquest programa, `omarchy crash mute hyprland off` les torna, i `omarchy crash mute` pel seu compte enumera el que heu silenciat. Accepta la ruta del binari tan bé com el seu nom, de manera que `omarchy crash mute /usr/bin/hyprland` fa el mateix. Poseu entre cometes un nom amb un espai, com a `omarchy crash mute 'Some App'`. Tota la resta continua notificant, i el programa silenciat continua fallant — això amaga el recordatori, no arregla res.

### Aplicacions d'escriptori

El menú _Instal·la > IA_ també porta algunes aplicacions gràfiques d'IA: l'aplicació d'escriptori de ChatGPT, l'aplicació d'escriptori de Claude (la beta de Linux d'Anthropic, amb pestanyes Chat, Cowork i Claude Code), Grok Bot per xatejar amb els models de xAI, Hermes Desktop, OpenClaw i l'aplicació d'escriptori de Perplexity. Grok Bot és l'aplicació de xat d'escriptori. L'agent de codificació és l'ordre `grok`.

Hermes Desktop és el que cal conèixer, perquè una màquina té un Hermes, i és el de l'aplicació: Hermes només s'instal·la mai mitjançant l'aplicació, i l'ordre `hermes` que l'agent per defecte executa és la de l'aplicació. Triar Hermes com a agent per defecte instal·la el mateix que instal·la l'entrada _Instal·la > IA_: el paquet i un entorn d'execució Hermes a `~/.hermes` configurat pel mateix instal·lador de Hermes, cosa que triga uns minuts la primera vegada. Aquest entorn és l'únic Hermes que fan servir l'ordre de terminal `hermes`, l'agent per defecte i l'aplicació, i s'actualitza sol amb `hermes update` en lloc d'esperar una versió d'Omarchy. Instal·lar-lo també lliura a Hermes el tema d'Omarchy com a skin anomenada `omarchy`, que cada superfície de Hermes segueix mentre canvieu de temes; trieu-ne una altra a la configuració Aparença de Hermes o amb `/skin` si preferiu que no ho faci, i Omarchy deixa aquesta elecció tranquil·la. Eliminar l'aplicació a _Elimina > IA_ tanca primer Hermes, passarel·la inclosa, s'emporta aquest entorn i conserva els vostres xats, records i les skills que Hermes va escriure per a si mateix tret que digueu el contrari: pregunta, amb no per defecte, si aquestes dades i la vostra configuració de connexió també han de marxar.

L'experiència d'escriptori d'OpenClaw és la seva Control UI, que s'obre com a aplicació web recolzada per la seva pròpia passarel·la local. OpenClaw viu a `~/.openclaw` i s'actualitza sol: feu servir el botó "Update Gateway" de la Control UI o executeu `openclaw update`, i la passarel·la es reinicia amb la versió nova. Omarchy només tria la versió des de la qual comença una instal·lació nova. Eliminar OpenClaw a _Elimina > IA_ s'emporta el servei de passarel·la i l'aplicació i després pregunta si `~/.openclaw` també ha de marxar, perquè això conté els vostres xats i credencials juntament amb el mateix OpenClaw i els entorns de complements que baixa; per defecte ho conserva, i instal·lar OpenClaw de nou ho recull.

### LLM locals

Omarchy recomana dues maneres d'executar models LLM locals: LM Studio i Ollama. LM Studio proporciona una interfície gràfica per trobar models de pesos oberts, instal·lar-los i executar-los. És una manera fantàstica de començar fàcilment. Ollama ofereix una CLI per fer-ho de manera semblant. Però si sou nous en models locals, jo començaria amb LM Studio. Podeu instal·lar-ne qualsevol dels dos a _Instal·la > IA_ al menú d'Omarchy.

### La Skill d'Omarchy

Les skills d'agent ajuden la IA a fer servir eines concretes d'una manera concreta, i Omarchy ve amb una skill per defecte per adaptar el sistema. Com retocar la vostra configuració de Hyprland, ajustar la barra o fins i tot crear un tema nou des de zero. Està enllaçada simbòlicament als directoris de skills de Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i cada `~/.hermes/profiles/*/skills`) i la ubicació genèrica `~/.agents/skills`, de manera que la majoria d'arnesos la recullen automàticament.

Però heu de tractar aquesta skill com a experimental. Models diferents la faran servir amb efectes diferents. És millor executar-la primer en mode de pla, perquè tingueu una idea del que l'agent voldria canviar. I després estigueu preparats per revertir els canvis o fins i tot invocar `omarchy reinstall configs`, si l'agent fa un embolic amb tot.
