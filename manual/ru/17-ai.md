# ИИ

Omarchy относится к ИИ-агентам кодирования как к первоклассным гражданам, но не выбирает фаворита за вас. Вместо этого каждый крупный CLI агента кодирования поставляется предварительно подключённым как лениво загружаемый лаунчер. Лаунчеры — это крошечные заглушки, управляемые [mise](https://mise.jdx.dev/), в `~/.local/bin/`, поэтому ничего не скачивается, пока вы впервые не запустите один из них. Hermes — исключение: для него ничего не заглушено, и выбор его устанавливает Hermes Desktop, как объясняет раздел _Desktop apps_ ниже. Вызывайте любой из этих и проходите аутентификацию при запросе:

| Команда    | Агент                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) от xAI                        |
| `pi`       | [Mario Zechner's Pi](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), оболочка OpenRouter |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), агент Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai), агент кодирования Meta           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` — не такой, как все: он запускает другие оболочки против всего каталога моделей OpenRouter, поэтому `ori claude`, `ori codex` или `ori opencode` запускают этих агентов на любой модели, на которую вы их направите, а `ori code` — собственный агент Ori.

Чтобы обернуть дополнительный CLI таким же образом, выполните `omarchy-mise-install <package> [command-name]`. Заглушки поддерживаются в актуальном состоянии вместе со всем остальным, чем управляет mise, при выполнении `omarchy update` (или псевдонима `mup`).

`grok` устанавливается через первоклассный пакет mise `grok`, так же как `claude` и `codex`. Выполните `grok` или выберите его в _Настройка > По умолчанию > Агент_. Пропустите установщик `curl | bash` на x.ai. Этот путь помещает вторую копию в `~/.grok/bin`, ставит её впереди в `PATH` и перезаписывает обёртку Omarchy.

### Агент по умолчанию

Выбрать агента по умолчанию можно через `omarchy default agent <name>` или в _Настройка > По умолчанию > Агент_ в меню Omarchy (`Super + Space`). Если агент ещё не установлен, выбор его сначала установит. Свежая Omarchy пригласит вас сделать этот выбор одноразовым уведомлением.

Выбор Claude также пытается настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может попросить ваш системный пароль; отмена или неудачная установка расширения всё равно выбирает и запускает Claude. Перезапустите браузер, включите расширение при запросе и войдите в Claude, чтобы завершить подключение. Выполните `/chrome` в Claude, чтобы проверить соединение. Firefox и Zen не поддерживают это расширение. Если Claude уже был вашим агентом по умолчанию до добавления этой настройки, выберите его снова, чтобы установить расширение.

[Muse Code](https://dev.meta.ai) — `muse` от Meta — использует предустановленную заглушку mise, как и другие агенты. Выбор его в качестве агента по умолчанию устанавливает официальный лаунчер Meta через HTTP-бэкенд mise. Лаунчер проверяет и обновляет нативный бинарник для вашей машины.

После выбора `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или открывает выбор, если вы ещё не выбрали). Также можно запустить его прямо в задачу через `omarchy agent prompt "Review this project"`. Агенты, запущенные таким образом, работают без надзора в своих режимах без остановки для вопросов, поэтому будьте готовы к тому, что они действительно будут что-то делать! А поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` стартуют вместо этого в `~/Work`.

Есть также ярлыки терминала: `a` запускает агента по умолчанию прямо в текущем терминале, а `c`, `cx` и `cy` запускают OpenCode, Claude Code и Codex напрямую (снова в их режимах авто-одобрения). Смена темы также синхронизируется с агентами: Claude Code, Pi, OpenCode и Hermes (после того как Omarchy его установила) все следуют за сменой темы Omarchy.

### Панель агентов

На верхней панели есть значок агентов. Пока вы не настроили агента, его панель проводит вас через вход в Claude, Codex или Grok, и первый становится вашим агентом по умолчанию. После этого панель собирает каждую подписку на одной странице: каждый агент и аккаунт с его планом, счётчик для каждого из 5-часовых сессионных и недельных лимитов с временем до сброса (наведите для точного процента) или остатком предоплаченного баланса, под строкой, которая ротируется через то, что вы использовали по всем ним, например токены за эту неделю и вашу самую используемую модель. В разделе _Make something_ она предлагает стартовые подсказки для новой темы, плагина или приложения, которые передают задачу вашему агенту по умолчанию. Приложения строятся так же, как собственные Hype, Monologue и Omacut Omarchy, на C++ и Qt Quick, следуя навыку агента omarchy-app, а компилятор и части Qt, которые им нужны, поставляются установленными. Claude Code, Codex, Grok и Fireworks охвачены из коробки.

Щёлкните левой кнопкой мыши по значку панели для панели, правой — чтобы запустить агента по умолчанию. Записи об использовании за ней перегенерируются каждые 15 минут через `omarchy agent usage-update`, а панель даже может объединять использование с других машин через синхронизируемую папку. См. README в `$OMARCHY_PATH/shell/plugins/agents/` для полных настроек.

### Несколько подписок

Если вы платите за более чем один план Claude, Codex или Grok — личный Max и рабочий, скажем, — Omarchy может держать их все вошедшими и перемещаться между ними. Добавьте подписку через + в панели агентов, которая проводит вас через это прямо там, или через `omarchy agent account add claude Work` (или `codex`, или `grok`). Это установит CLI, если он отсутствует. Первый аккаунт провайдера входит через ваш обычный браузер, именно там, куда CLI всегда смотрит. Каждый последующий входит через приватное окно, чтобы аккаунт, в который ваш браузер уже вошёл, не был выбран по ошибке; войдите там как аккаунт, который добавляете, и сначала закройте любое приватное окно, которое у вас уже открыто. Никогда не выходите из CLI для этого: выход отзывает сохранённый вход, и этот аккаунт пришлось бы добавлять снова.

Один аккаунт на провайдера активен, и каждая новая сессия начинается как он: `cx`, `cy`, обычный `claude`, `codex` или `grok`, всё, запущенное через `omarchy agent`, и скрипты или редакторы, находящие CLI в `PATH`. Переключайтесь через `omarchy agent account use work` (и обратно через `omarchy agent account use main`) или в панели, нажав номер аккаунта, а затем `Enter` (или щёлкнув по его кнопке Use). Уже запущенные сессии остаются на аккаунте, с которым стартовали. История разговоров, настройки, навыки и плагины разделяются между аккаунтами, поэтому `claude --continue` в той же папке продолжает с места, где вы остановились, на новом аккаунте.

При нескольких аккаунтах панель показывает лимиты каждого аккаунта бок о бок, с отметкой активного. По умолчанию Omarchy уведомляет вас, когда активный аккаунт проходит 95% лимита, и щелчок по уведомлению переключает на аккаунт с наибольшим запасом. Наведите курсор на строку аккаунта в панели и щёлкните по Autoswitch, который появляется рядом с Use (или нажмите `m`), или выполните `omarchy agent account mode auto`, чтобы переключение происходило само; пока оно включено, Autoswitch занимает место Use, а повторный щелчок возвращает к уведомлениям. Добавьте число, чтобы изменить порог, как в `omarchy agent account mode auto 90`. Если каждый аккаунт превышает порог, вы услышите об этом один раз вместе с тем, какой аккаунт освободится первым. Пока активный аккаунт находится в пределах 15 пунктов от своего порога (80% по умолчанию), его лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждый аккаунт и его последние лимиты, `omarchy agent account remove work` забывает один, а `omarchy agent account rename primary Hey` переименовывает (или щёлкните по имени аккаунта в панели). Эти команды работают с аккаунтами вашего агента по умолчанию; чтобы добраться до другого провайдера, назовите его сначала, как в `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, — это аккаунт _Main_, и он остаётся на месте. Аккаунт, не использовавшийся более восьми часов, может показать _Sign-in required_; щёлкните по нему, чтобы снова войти в этот аккаунт прямо в панели, или запустите сессию в нём, что само обновит вход. MCP-серверы, которые у вас были при добавлении аккаунта, приходят вместе с ним, но те, которые вы добавите позже через `claude mcp add`, дойдут только до аккаунта, в котором вы их добавили. Claude Desktop и инструменты, настроенные на абсолютный путь к бинарнику CLI, не следуют за переключением. Явный `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеет приоритет над выбранным аккаунтом.

### Диагностика сбоев

Omarchy следит за systemd-coredump на предмет сбоев процессов. Когда что-то сегфолтится, вы получите уведомление «Process crashed» — щёлкните по нему, и сбой будет передан вашему агенту по умолчанию вместе с навыком diagnose-crash Omarchy, который проводит агента через установление фактов из дампа ядра и решение, стоит ли сообщать о сбое вверх по течению. Также можно запустить его вручную против любого PID из `coredumpctl list` через `omarchy agent crash <pid>`.

Наблюдение включено по умолчанию. Выключите его в _Действия > Переключить > Отлов сбоев_ (или через `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушать по одной программе за раз, что диагностика и предлагает в конце. `omarchy crash mute hyprland` останавливает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их, а `omarchy crash mute` сам по себе перечисляет заглушённое. Он принимает путь бинарника так же охотно, как и его имя, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключайте имя с пробелом в кавычки, как в `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушённая программа по-прежнему падает — это скрывает напоминание, а не исправляет что-либо.

### Десктопные приложения

Меню _Установить > ИИ_ также содержит несколько графических ИИ-приложений: десктопное приложение ChatGPT, десктопное приложение Claude (Linux-бета Anthropic с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Hermes Desktop, OpenClaw и десктопное приложение Perplexity. Grok Bot — десктопное чат-приложение. Агент кодирования — команда `grok`.

Hermes Desktop — тот, о котором стоит знать, потому что на машине один Hermes, и он принадлежит приложению: Hermes устанавливается только через приложение, а команда `hermes`, которую запускает агент по умолчанию, — приложения. Выбор Hermes в качестве агента по умолчанию устанавливает то же самое, что делает пункт _Установить > ИИ_: пакет и рантайм Hermes в `~/.hermes`, настроенный собственным установщиком Hermes, что в первый раз занимает несколько минут. Этот рантайм — тот самый Hermes, который используют терминальная команда `hermes`, агент по умолчанию и приложение, и он обновляется сам через `hermes update`, а не ждёт релиза Omarchy. Установка его также передаёт Hermes тему Omarchy в виде скина с именем `omarchy`, которому следует каждая поверхность Hermes при смене тем; выберите другой в настройках Appearance Hermes или через `/skin`, если не хотите этого, и Omarchy оставит этот выбор в покое. Удаление приложения в _Удалить > ИИ_ сначала закрывает Hermes, включая шлюз, забирает этот рантайм с собой и сохраняет ваши чаты, воспоминания и навыки, которые Hermes написал для себя, если вы не скажете иначе: оно спрашивает, по умолчанию нет, должны ли эти данные и ваши настройки подключения тоже уйти.

Десктопный опыт OpenClaw — его Control UI, который открывается как веб-приложение, поддерживаемое собственным локальным шлюзом. OpenClaw живёт в `~/.openclaw` и обновляется сам: используйте кнопку «Update Gateway» в Control UI или выполните `openclaw update`, и шлюз перезапустится на новой версии. Omarchy только выбирает релиз, с которого начинается свежая установка. Удаление OpenClaw в _Удалить > ИИ_ забирает службу шлюза и приложение с собой, а затем спрашивает, должен ли `~/.openclaw` тоже уйти, поскольку там хранятся ваши чаты и учётные данные рядом с самим OpenClaw и рантаймами плагинов, которые он скачивает; по умолчанию он сохраняется, а повторная установка OpenClaw снова его подбирает.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет GUI-интерфейс для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для того же. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Установить любой из них можно в _Установить > ИИ_ в меню Omarchy.

### Навык Omarchy

Навыки агентов помогают ИИ использовать конкретные инструменты определённым образом, и Omarchy поставляется с навыком по умолчанию для настройки системы. Например, настройка вашей конфигурации Hyprland, регулировка панели или даже создание новой темы с нуля. Он симлинкуется в каталоги навыков для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждый `~/.hermes/profiles/*/skills`) и общее расположение `~/.agents/skills`, поэтому большинство оболочек подбирают его автоматически.

Но к этому навыку следует относиться как к экспериментальному. Разные модели будут использовать его с разным эффектом. Лучше сначала запустить в режиме плана, чтобы иметь представление о том, что агент хотел бы изменить. А затем быть готовым откатить изменения или даже вызвать `omarchy reinstall configs`, если агент устроит беспорядок.
