# IA

O Omarchy trata agentes de codificação por IA como cidadãos de primeira classe, mas não escolhe um favorito para você. Em vez disso, toda CLI importante de agente de codificação vem pré-conectada como um iniciador de carregamento preguiçoso. Os iniciadores são pequenos stubs gerenciados pelo [mise](https://mise.jdx.dev/) em `~/.local/bin/`, então nada é baixado até a primeira vez que você realmente executar um. O Hermes é a exceção: nada é um stub para ele, e escolhê-lo instala o Hermes Desktop, como _Aplicativos de desktop_ abaixo explica. Invoque qualquer um deles e autentique-se quando solicitado:

| Comando    | Agente                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) da xAI                        |
| `pi`       | [Pi de Mario Zechner](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), o harness da OpenRouter |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), o agente da Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai), o agente de codificação da Meta           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

O `ori` é o diferente: ele executa os outros harnesses contra todo o catálogo de modelos da OpenRouter, então `ori claude`, `ori codex` ou `ori opencode` iniciam esses agentes em qualquer modelo para o qual você os aponte, e `ori code` é o agente do próprio Ori.

Para embrulhar uma CLI adicional do mesmo jeito, execute `omarchy-mise-install <package> [command-name]`. Os stubs são mantidos atualizados junto com todo o resto que o mise gerencia quando você executa `omarchy update` (ou o alias `mup`).

O `grok` é instalado pelo pacote `grok` próprio do mise, do mesmo jeito que o `claude` e o `codex`. Execute `grok`, ou escolha-o em _Configuração > Padrões > Agente_. Pule o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, a coloca no início do `PATH` e sobrescreve o wrapper do Omarchy.

### O agente padrão

Escolha seu agente padrão com `omarchy default agent <name>` ou em _Configuração > Padrões > Agente_ no Menu do Omarchy (`Super + Space`). Se o agente ainda não estiver instalado, escolhê-lo o instala primeiro. Um Omarchy novo convidará você a fazer essa escolha com uma notificação única.

Escolher o Claude também tenta configurar sua extensão de navegador para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão se aplica a todos os usuários e pode pedir sua senha do sistema; cancelar ou uma instalação da extensão com falha ainda seleciona e abre o Claude. Reinicie seu navegador, ative a extensão se solicitado e entre no Claude para terminar de conectá-la. Execute `/chrome` no Claude para verificar a conexão. Firefox e Zen não suportam essa extensão. Se o Claude já era seu padrão antes de essa configuração ser adicionada, selecione-o de novo para instalar a extensão.

O [Muse Code](https://dev.meta.ai) — o `muse` da Meta — usa um stub mise pré-instalado como os outros agentes. Escolhê-lo como padrão instala o iniciador oficial da Meta pelo backend HTTP do mise. O iniciador verifica e atualiza o binário nativo para a sua máquina.

Depois que você escolher, `Super + Shift + Ctrl + A` abre o agente padrão em uma janela de terminal dedicada (ou abre o seletor se você ainda não escolheu). Você também pode abri-lo direto em uma tarefa com `omarchy agent prompt "Review this project"`. Agentes abertos assim rodam sem supervisão em seus respectivos modos de não parar para perguntar, então esteja pronto para eles realmente fazerem coisas! E, como os agentes se recusam a lembrar confiança para o seu diretório home, inícios a partir do `$HOME` começam em `~/Work`.

Há atalhos de terminal também: `a` executa o agente padrão inline no terminal atual, enquanto `c`, `cx` e `cy` iniciam OpenCode, Claude Code e Codex diretamente (novamente em seus modos de aprovação automática). Mudanças de tema também sincronizam com os agentes: Claude Code, Pi, OpenCode e Hermes (depois que o Omarchy o instalou) acompanham quando você muda o tema do Omarchy.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de você configurar um agente, seu painel guia você para entrar no Claude, Codex ou Grok, e o primeiro se torna seu agente padrão. Depois disso, o painel coloca toda assinatura em uma página: cada agente e conta com seu plano, um medidor para cada um de seus limites de sessão de 5 horas e semanais com o tempo até ele se redefinir (passe o mouse para a porcentagem exata), ou o saldo pré-pago restante, sob uma linha que alterna o que você usou entre todos eles, como tokens nesta semana e seu modelo mais usado. Em _Criar algo_, ele oferece prompts iniciais para um novo tema, plugin ou aplicativo que entregam a tarefa ao seu agente padrão. Aplicativos são construídos do jeito que os próprios Hype, Monologue e Omacut do Omarchy são, em C++ e Qt Quick, seguindo a skill de agente omarchy-app, e o compilador e as peças do Qt de que eles precisam já vêm instalados. Claude Code, Codex, Grok e Fireworks são cobertos de imediato.

Clique com o botão esquerdo no ícone da barra para o painel, com o botão direito para abrir seu agente padrão. Os registros de uso por trás dele são regenerados a cada 15 minutos por `omarchy agent usage-update`, e o painel pode até mesclar uso das suas outras máquinas por uma pasta sincronizada. Veja o README em `$OMARCHY_PATH/shell/plugins/agents/` para as configurações completas.

### Várias assinaturas

Se você paga por mais de um plano do Claude, do Codex ou do Grok — um Max pessoal e um do trabalho, digamos — o Omarchy pode manter todos conectados e se mover entre eles. Adicione uma assinatura com o + no painel de agentes, que guia você ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Ele instala a CLI se ela estiver faltando. A primeira conta de um provedor entra pelo seu navegador normal, bem onde a CLI sempre procura. Todas as seguintes entram por uma janela privativa, para que a conta em que seu navegador já está conectado não seja pega por engano; entre lá como a conta que você está adicionando e feche antes qualquer janela privativa que você já tinha aberta. Nunca saia da CLI para fazer isso: sair revoga o login salvo, e aquela conta teria que ser adicionada de novo.

Uma conta por provedor fica ativa, e toda nova sessão começa como ela: `cx`, `cy`, um `claude`, `codex` ou `grok` simples, qualquer coisa aberta por `omarchy agent`, e scripts ou editores que encontram a CLI no `PATH`. Mude com `omarchy agent account use work` (e de volta com `omarchy agent account use main`), ou no painel pressionando o número de uma conta e depois `Enter` (ou clicando no botão Usar dela). Sessões já em execução permanecem na conta com a qual começaram. Histórico de conversas, configurações, skills e plugins são compartilhados entre contas, então `claude --continue` na mesma pasta retoma de onde você parou na nova conta.

Com mais de uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa marcada. Por padrão, o Omarchy notifica você quando a conta ativa passa de 95% de um limite, e clicar na notificação muda para a conta com mais folga. Passe o mouse sobre a linha de uma conta no painel e clique em Troca automática que aparece ao lado de Usar (ou pressione `m`), ou execute `omarchy agent account mode auto`, para que ele mude sozinho; enquanto estiver ligado, Troca automática toma o lugar de Usar, e clicar de novo volta a notificar. Adicione um número para mudar o limite, como em `omarchy agent account mode auto 90`. Se todas as contas estiverem acima do limite, você saberá disso uma vez, junto com qual conta se libera primeiro. Enquanto uma conta ativa estiver a até 15 pontos do seu limite (80% no padrão), seus limites são verificados a cada três minutos, em vez de a cada 15.

`omarchy agent account list` mostra todas as contas e seus limites mais recentes, `omarchy agent account remove work` esquece uma e `omarchy agent account rename primary Hey` renomeia uma (ou clique no nome de uma conta no painel). Esses comandos funcionam nas contas do seu agente padrão; para alcançar o outro provedor, nomeie-o primeiro, como em `omarchy agent account use codex side`. O login que você já tinha em `~/.claude` ou `~/.codex` é a conta _Main_ e permanece onde está. Uma conta deixada sem uso por mais de cerca de oito horas pode mostrar _Login necessário_; clique nela para entrar naquela conta novamente bem no painel, ou inicie uma sessão nela, o que renova o login sozinho. Servidores MCP que você tinha quando uma conta foi adicionada a acompanham, mas os que você adicionar depois com `claude mcp add` só alcançam a conta em que você os adicionou. O Claude Desktop e ferramentas configuradas com um caminho absoluto para um binário da CLI não seguem a mudança. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de crashes

O Omarchy observa o systemd-coredump em busca de crashes de processos. Quando algo sofre segfault, você receberá uma notificação "Process crashed" — clique nela, e o crash é entregue ao seu agente padrão junto com a skill diagnose-crash do Omarchy, que guia o agente a estabelecer os fatos a partir do core dump e decidir se vale a pena relatar o crash upstream. Você também pode executá-la manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A observação vem ligada por padrão. Desligue-a em _Acionar > Alternar > Captura de Crashes_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` ainda funciona manualmente.

Crashes também podem ser silenciados um programa por vez, que é o que o diagnóstico oferece a você no fim. `omarchy crash mute hyprland` interrompe as notificações só para aquele programa, `omarchy crash mute hyprland off` as traz de volta e `omarchy crash mute` sozinho lista o que você silenciou. Ele aceita o caminho do binário com a mesma facilidade que seu nome, então `omarchy crash mute /usr/bin/hyprland` faz a mesma coisa. Coloque entre aspas um nome com espaço, como em `omarchy crash mute 'Some App'`. Todo o resto continua notificando, e o programa silenciado continua crashando — isso oculta o lembrete, não conserta nada.

### Aplicativos de desktop

O menu _Instalar > IA_ também traz alguns aplicativos gráficos de IA: o aplicativo de desktop do ChatGPT, o aplicativo de desktop do Claude (o beta Linux da Anthropic, com as abas Chat, Cowork e Claude Code), o Grok Bot para conversar com os modelos da xAI, o Hermes Desktop, o OpenClaw e o aplicativo de desktop do Perplexity. O Grok Bot é o aplicativo de chat de desktop. O agente de codificação é o comando `grok`.

O Hermes Desktop é o que merece ser conhecido, porque uma máquina tem um Hermes, e ele é o do aplicativo: o Hermes só é instalado pelo aplicativo, e o comando `hermes` que o agente padrão executa é o do aplicativo. Escolher o Hermes como agente padrão instala a mesma coisa que a entrada _Instalar > IA_: o pacote, e um runtime do Hermes em `~/.hermes` configurado pelo próprio instalador do Hermes, o que leva alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` do terminal, o agente padrão e o aplicativo usam, e ele se atualiza com `hermes update` em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema do Omarchy como uma skin chamada `omarchy`, que toda superfície do Hermes segue conforme você muda de temas; escolha outra nas configurações de Aparência do Hermes ou com `/skin` se prefere que ele não faça isso, e o Omarchy deixa essa escolha em paz. Remover o aplicativo em _Remover > IA_ fecha o Hermes primeiro, gateway incluído, leva aquele runtime com ele e mantém seus chats, suas memórias e as skills que o Hermes escreveu para si, a menos que você lhe diga o contrário: ele pergunta, com padrão não, se esses dados e suas configurações de conexão também devem ir.

A experiência de desktop do OpenClaw é sua Control UI, que abre como um aplicativo web sustentado por seu próprio gateway local. O OpenClaw vive em `~/.openclaw` e se atualiza sozinho: use o botão "Update Gateway" da Control UI ou execute `openclaw update`, e o gateway reinicia na nova versão. O Omarchy só escolhe a versão da qual uma instalação nova parte. Remover o OpenClaw em _Remover > IA_ leva o serviço do gateway e o aplicativo com ele e depois pergunta se `~/.openclaw` também deve ir, já que isso guarda seus chats e suas credenciais junto com o próprio OpenClaw e os runtimes de plugin que ele baixa; o padrão o mantém, e instalar o OpenClaw de novo o retoma.

### LLMs locais

O Omarchy recomenda duas maneiras de executar modelos LLM locais: LM Studio e Ollama. O LM Studio fornece uma interface gráfica para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma ótima maneira de começar facilmente. O Ollama oferece uma CLI para fazer isso de forma semelhante. Mas, se você é novo em modelos locais, eu começaria pelo LM Studio. Você pode instalar qualquer um em _Instalar > IA_ no Menu do Omarchy.

### A Skill do Omarchy

Skills de agente ajudam a IA a usar ferramentas específicas de uma maneira específica, e o Omarchy vem com uma skill padrão para adaptar o sistema. Como ajustar sua configuração do Hyprland, a barra, ou até criar um novo tema do zero. Ela é vinculada simbolicamente aos diretórios de skills do Claude Code (`~/.claude/skills`), do Codex (`~/.codex/skills`), do Pi (`~/.pi/agent/skills`), do Antigravity (`~/.gemini/config/skills`), do Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`) e ao local genérico `~/.agents/skills`, então a maioria dos harnesses a capta automaticamente.

Mas você deve tratar essa skill como experimental. Modelos diferentes a usarão com efeitos diferentes. É melhor executar primeiro em modo de planejamento, para ter uma ideia do que o agente gostaria de mudar. E depois estar pronto para reverter mudanças ou até invocar `omarchy reinstall configs`, se o agente fizer uma bagunça em tudo.
