# AI

Omarchy 把 AI 程式設計代理程式視為一等公民，但它不會替你挑一個最愛。取而代之的是，每一個主要的程式設計代理程式 CLI 都預先接好成為一個延遲載入的啟動器。這些啟動器是位於 `~/.local/bin/` 中、由 [mise](https://mise.jdx.dev/) 管理的小型存根，所以在你實際第一次運行其中一個之前，什麼都還沒被下載。Hermes 是例外：它沒有被存根化，選擇它會安裝 Hermes Desktop，如下方的_桌面應用程式_所述。呼叫其中任何一個，並在出現提示時進行驗證：

| 指令    | 代理程式                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build)，來自 xAI                        |
| `pi`       | [Mario Zechner's Pi](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), OpenRouter 的 harness |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), Nous Research 的代理程式  |
| `muse`     | [Muse Code](https://dev.meta.ai), Meta 的程式設計代理程式           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` 是其中的異類：它讓其他 harness 在 OpenRouter 的整個模型目錄上運行，所以 `ori claude`、`ori codex` 或 `ori opencode` 會在你指向的任何模型上啟動那些代理程式，而 `ori code` 則是 Ori 自己的代理程式。

若要以相同的方式包裝一個額外的 CLI，請執行 `omarchy-mise-install <package> [command-name]`。當你執行 `omarchy update`（或 `mup` 別名）時，這些存根會和 mise 管理的其他一切一起保持在最新狀態。

`grok` 透過 mise 第一方的 `grok` 套件來安裝，與 `claude` 和 `codex` 相同。執行 `grok`，或在 _設定 > 預設值 > 代理程式_ 底下選它。跳過 x.ai 上的 `curl | bash` 安裝程式。那條路徑會在 `~/.grok/bin` 中放第二份副本、把自己前置到 `PATH` 上，並覆寫 Omarchy 的包裝器。

### 預設代理程式

用 `omarchy default agent <name>`，或在 Omarchy 選單（`Super + Space`）的 _設定 > 預設值 > 代理程式_ 底下，來選你的預設代理程式。如果該代理程式還沒安裝，選擇它會先把它安裝起來。一個全新的 Omarchy 會用一則一次性通知邀請你做出這個選擇。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 和 Edge 設定它的瀏覽器擴充功能。該擴充功能設定適用於所有使用者，並可能要求你的系統密碼；取消或擴充功能安裝失敗，仍會選取並啟動 Claude。重新啟動你的瀏覽器、在出現提示時啟用該擴充功能，並登入 Claude 以完成連接。在 Claude 中執行 `/chrome` 來檢查連線。Firefox 和 Zen 不支援這個擴充功能。如果在加入這套設定之前，Claude 已經是你的預設，請再次選取它來安裝該擴充功能。

[Muse Code](https://dev.meta.ai)——Meta 的 `muse`——像其他代理程式一樣使用一個預先安裝的 mise 存根。把它選為預設會透過 mise 的 HTTP 後端安裝 Meta 的官方啟動器。該啟動器會驗證並更新你機器適用的原生二進位檔。

一旦你選好了，`Super + Shift + Ctrl + A` 會在一個專屬的終端機視窗中啟動預設代理程式（如果你還沒選，則會帶出選擇器）。你也可以用 `omarchy agent prompt "Review this project"` 讓它直接帶著一個任務啟動。以這種方式啟動的代理程式，會以它們各自那種不停下來詢問的模式無人值守地運行，所以請做好它們真的會動手的準備！而且由於代理程式拒絕為你的家目錄記住信任，從 `$HOME` 啟動時會改在 `~/Work` 中開始。

還有終端機捷徑：`a` 在目前的終端機中直接執行預設代理程式，而 `c`、`cx` 和 `cy` 則直接啟動 OpenCode、Claude Code 和 Codex（同樣是在它們的自動核准模式中）。主題變更也會同步到代理程式：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已經安裝了它）全都會跟進。

### 代理程式面板

選單列有一個代理程式圖示。在你設定好一個代理程式之前，它的面板會引導你登入 Claude、Codex 或 Grok，而第一個會成為你的預設代理程式。之後，該面板會把每一個訂閱放在同一個頁面上：每一個代理程式和帳戶，連同它的方案、它 5 小時工作階段和每週上限各自的計量表與重設前的剩餘時間（懸停可查看確切百分比），或者剩餘的預付餘額，全部位於一行文字之下，那行文字會輪流顯示你在它們全部之上的使用量，例如本週的 tokens 和你最常用的模型。在_動手做點東西_底下，它會為新主題、外掛或應用程式提供起始提示，把任務交給你的預設代理程式。應用程式的建置方式，就像 Omarchy 自己的 Hype、Monologue 和 Omacut 一樣，以 C++ 和 Qt Quick 完成，遵循 omarchy-app 代理程式技能，而它們需要的編譯器和 Qt 元件都已預先安裝。Claude Code、Codex、Grok 和 Fireworks 都是開箱即用的。

左鍵點選選單列圖示開啟面板，右鍵點選啟動你的預設代理程式。它背後的使用紀錄由 `omarchy agent usage-update` 每 15 分鐘重新產生一次，而該面板甚至可以透過一個同步資料夾合併你其他機器的使用量。完整設定見 `$OMARCHY_PATH/shell/plugins/agents/` 底下的 README。

### 多個訂閱

如果你付費訂閱了不只一個 Claude、Codex 或 Grok 方案——比如一個個人的 Max 和一個工作的——Omarchy 可以讓它們全部保持登入，並在它們之間移動。用代理程式面板中的 + 新增一個訂閱，它會在那裡直接引導你完成，或用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果 CLI 不存在，它會把它安裝起來。某個提供者的第一個帳戶，會透過你一般的瀏覽器，在 CLI 一直尋找登入的地方登入。之後的每一個則透過私密視窗登入，所以你的瀏覽器已經登入的那個帳戶不會被誤選；在那裡以你要新增的帳戶登入，並先關閉你已經開啟的任何私密視窗。永遠不要為了做這件事而登出 CLI：登出會撤銷已儲存的登入，而那個帳戶就必須重新新增。

每個提供者有一個作用中的帳戶，而每一個新的工作階段都以它開始：`cx`、`cy`、單純的 `claude`、`codex` 或 `grok`、任何透過 `omarchy agent` 啟動的東西，以及在 `PATH` 上找到 CLI 的腳本或編輯器。用 `omarchy agent account use work` 切換（用 `omarchy agent account use main` 切回來），或在面板中按下某個帳戶的數字然後按 `Enter`（或點選它的「使用」按鈕）。已經在運行的工作階段會留在它們開始時的那個帳戶上。對話紀錄、設定、技能和外掛在帳戶之間共享，所以在同一個資料夾中執行 `claude --continue`，會在新帳戶上從你離開的地方繼續。

當有不只一個帳戶時，面板會並排顯示每個帳戶的上限，並標記作用中的那個。預設情況下，當作用中帳戶超過某個上限的 95% 時，Omarchy 會通知你，而點選該通知會切換到尚有最多餘量的一個帳戶。將指標懸停在面板中某個帳戶的那一行，點選出現在「使用」旁邊的「自動切換」（或按下 `m`），或執行 `omarchy agent account mode auto`，即可讓它自行切換；當它開啟時，「自動切換」會取代「使用」的位置，再點一次則回到通知。加上一個數字可以變更閾值，例如 `omarchy agent account mode auto 90`。如果每一個帳戶都超過了閾值，你會聽到一次，連同哪個帳戶最先釋放出額度。當一個作用中帳戶在其閾值的 15 個百分點以內時（預設為 80%），它的上限會每三分鐘檢查一次，而不是每 15 分鐘一次。

`omarchy agent account list` 顯示每一個帳戶及其最新上限，`omarchy agent account remove work` 忘記一個，而 `omarchy agent account rename primary Hey` 重新命名一個（或在面板中點選帳戶名稱）。這些指令作用於你預設代理程式的帳戶；若要存取另一個提供者，請先點名它，例如 `omarchy agent account use codex side`。你已經在 `~/.claude` 或 `~/.codex` 中擁有的登入，就是 _Main_ 帳戶，並會留在原處。一個閒置超過約八小時未被使用的帳戶可能會顯示_需要登入_；點選它即可直接在面板中重新登入該帳戶，或在其中啟動一個工作階段，後者會自行重新整理登入。你在新增某個帳戶時擁有的 MCP 伺服器會跟著到那個帳戶，但你之後用 `claude mcp add` 新增的，則只會到達你新增它們的那個帳戶。Claude Desktop，以及以絕對路徑指向某個 CLI 二進位檔來設定的工具，不會跟隨此切換。一個明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 優先於所選的帳戶。

### 當機診斷

Omarchy 會監看 systemd-coredump 中的程序當機。當某個東西段錯誤時，你會收到一則「程序已當機」通知——點選它，那起當機就會連同 Omarchy 的 diagnose-crash 技能一起交給你的預設代理程式，該技能會引導代理程式從核心傾印建立事實，並決定這起當機是否值得回報給上游。你也可以用 `omarchy agent crash <pid>`，針對來自 `coredumpctl list` 的任何 PID 手動執行它。

監看預設開啟。在 _觸發 > 切換 > 當機擷取_ 底下把它關掉（或用 `omarchy toggle crash-capture`），通知就會停止；`omarchy agent crash <pid>` 仍可手動使用。

當機也可以一次針對一個程式靜音，那正是診斷在最後會提供給你的選項。`omarchy crash mute hyprland` 會停止僅針對該程式的通知，`omarchy crash mute hyprland off` 把它們帶回來，而單獨使用 `omarchy crash mute` 會列出你靜音了什麼。它接受二進位檔的路徑，一如接受它的名稱，所以 `omarchy crash mute /usr/bin/hyprland` 做的事相同。對帶有空格的名稱加上引號，例如 `omarchy crash mute 'Some App'`。其他一切仍然會通知，而被靜音的那個程式仍然會當機——這只是隱藏提醒，什麼都沒有修復。

### 桌面應用程式

_安裝 > AI_ 選單也提供一些圖形化 AI 應用程式：ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux 測試版，帶有 Chat、Cowork 和 Claude Code 分頁）、用於與 xAI 模型聊天的 Grok Bot、Hermes Desktop、OpenClaw，以及 Perplexity 桌面應用程式。Grok Bot 是桌面聊天應用程式。程式設計代理程式則是 `grok` 指令。

Hermes Desktop 是其中需要了解的一個，因為一台機器只有一個 Hermes，而且它屬於該應用程式：Hermes 只能永遠透過這個應用程式來安裝，而預設代理程式所運行的 `hermes` 指令也是那個應用程式的。把 Hermes 選為預設代理程式，安裝的東西與 _安裝 > AI_ 項目所安裝的相同：該套件，以及由 Hermes 自己的安裝程式所設定、位於 `~/.hermes` 底下的一個 Hermes 執行環境，它在第一次需要花上幾分鐘。那個執行環境就是唯一的 Hermes，終端機的 `hermes` 指令、預設代理程式和應用程式全都使用它，而它用 `hermes update` 自行更新，而不是等 Omarchy 發版。安裝它也會把 Omarchy 主題交給 Hermes 作為一個名為 `omarchy` 的外觀，在你切換主題時，每一個 Hermes 介面都會跟隨；如果你比較不希望如此，在 Hermes 的 Appearance 設定中或用 `/skin` 選另一個，而 Omarchy 會尊重那個選擇。在 _移除 > AI_ 底下移除該應用程式，會先關閉 Hermes，包括閘道，把那個執行環境一併帶走，並保留你的聊天、記憶和 Hermes 為它自己寫的技能，除非你另有指示：它會詢問，預設為否，問那些資料和你的連線設定是否也該一併移除。

OpenClaw 的桌面體驗是它的 Control UI，它以一個網頁應用程式的形式開啟，背後由它自己的本機閘道支撐。OpenClaw 位於 `~/.openclaw` 中並自行更新：使用 Control UI 的「更新閘道」按鈕，或執行 `openclaw update`，閘道就會在新版本上重新啟動。Omarchy 只選擇全新安裝的起始版本。在 _移除 > AI_ 底下移除 OpenClaw，會一併帶走閘道服務和應用程式，然後詢問 `~/.openclaw` 是否也該移除，因為它保存著你的聊天和憑證，以及 OpenClaw 本身和它所下載的外掛執行環境；預設為保留它，而再次安裝 OpenClaw 時會把它重新接回來。

### 本機 LLM

Omarchy 推薦兩種運行本機 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供一個 GUI 介面，用於尋找開放權重模型、安裝它們並運行它們。那是輕鬆上手的好方法。Ollama 則提供一個類似的 CLI。但如果你是本機模型的新手，我會從 LM Studio 開始。你可以在 Omarchy 選單的 _安裝 > AI_ 底下安裝其中任何一個。

### Omarchy 技能

代理程式技能幫助 AI 以特定的方式使用特定的工具，而 Omarchy 內建了一個用於訂製系統的預設技能。就像調整你的 Hyprland 設定、調整選單列，甚至從零建立一個新主題。它被符號連結進 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每一個 `~/.hermes/profiles/*/skills`），以及通用的 `~/.agents/skills` 位置，所以大多數 harness 會自動取用它。

但你應該把這個技能視為實驗性質。不同的模型使用它的效果會有所不同。最好先在計畫模式中運行，這樣你對代理程式想改變什麼心裡有數。然後，若代理程式把一切搞得一團亂，請做好回復變更、甚至呼叫 `omarchy reinstall configs` 的準備。
