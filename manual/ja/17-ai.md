# AI

Omarchy は AI コーディングエージェントを一級市民として扱いますが、あなたのために一番のお気に入りを選んだりはしません。代わりに、主要なコーディングエージェント CLI はすべて遅延読み込みランチャーとしてあらかじめ配線されています。ランチャーは `~/.local/bin/` にある小さな [mise](https://mise.jdx.dev/) 管理のスタブなので、実際に 1 つ実行するまで何もダウンロードされません。Hermes は例外です：そのスタブは何もなく、選ぶと Hermes Desktop がインストールされます。以下の _デスクトップアプリ_ で説明します。いずれかを呼び出して、求められたら認証してください：

| コマンド    | エージェント                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | xAI の [Grok Build](https://x.ai/build)                        |
| `pi`       | [Mario Zechner's Pi](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness)、OpenRouter のハーネス |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/)、Nous Research のエージェント  |
| `muse`     | [Muse Code](https://dev.meta.ai)、Meta のコーディングエージェント           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` は変わり者です：他のハーネスを OpenRouter の全モデルカタログに対して実行するので、`ori claude`、`ori codex`、`ori opencode` は、向けたモデルでそれらのエージェントを起動し、`ori code` は Ori 独自のエージェントです。

同じように追加の CLI をラップするには、`omarchy-mise-install <package> [command-name]` を実行してください。スタブは、`omarchy update`（または `mup` エイリアス）を実行したときに mise が管理する他のすべてのものと一緒に最新に保たれます。

`grok` は `claude` や `codex` と同じように、mise のファーストパーティ `grok` パッケージ経由でインストールされます。`grok` を実行するか、_設定 > デフォルト > エージェント_ の下で選んでください。x.ai の `curl | bash` インストーラーは避けてください。そのパスでは 2 つ目のコピーが `~/.grok/bin` に置かれ、`PATH` の先頭に追加され、Omarchy のラッパーを上書きします。

### デフォルトエージェント

デフォルトエージェントは `omarchy default agent <name>` で、または Omarchy メニュー（`Super + Space`）の _設定 > デフォルト > エージェント_ の下で選んでください。エージェントがまだインストールされていなければ、選ぶとまずインストールされます。新しい Omarchy は一度きりの通知でこの選択を促します。

Claude を選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge 用のブラウザ拡張機能のセットアップも試みます。拡張機能のセットアップはすべてのユーザーに適用され、システムパスワードを求める場合があります。キャンセルしたり拡張機能のインストールに失敗したりしても、Claude が選択されて起動します。ブラウザを再起動し、求められたら拡張機能を有効にし、Claude にサインインして接続を完了してください。接続を確認するには Claude で `/chrome` を実行してください。Firefox と Zen はこの拡張機能をサポートしていません。このセットアップが追加される前に Claude がすでにデフォルトだった場合は、再び選択して拡張機能をインストールしてください。

[Muse Code](https://dev.meta.ai)、Meta の `muse` は、他のエージェントと同様にプリインストールされた mise スタブを使います。それをデフォルトとして選ぶと、mise の HTTP バックエンド経由で Meta の公式ランチャーがインストールされます。ランチャーはあなたのマシン用のネイティブバイナリを検証し、更新します。

一度選んだら、`Super + Shift + Ctrl + A` でデフォルトエージェントが専用ターミナルウィンドウで起動します（まだ選んでいなければピッカーを表示します）。`omarchy agent prompt "Review this project"` でタスクに直接起動することもできます。この方法で起動したエージェントは、それぞれの「止まって聞かない」モードで無人で実行されるので、実際に何かをする準備をしてください！ そしてエージェントはホームディレクトリへの信頼を覚えることを拒否するので、`$HOME` からの起動は代わりに `~/Work` で始まります。

ターミナルショートカットもあります：`a` は現在のターミナルでデフォルトエージェントをインラインで実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動します（やはり自動承認モードで）。テーマの変更はエージェントにも同期します：Claude Code、Pi、OpenCode、Hermes（Omarchy がインストールした後は）はすべて、Omarchy テーマを切り替えると追従します。

### エージェントパネル

トップバーにはエージェントアイコンがあります。エージェントをセットアップする前は、そのパネルが Claude、Codex、Grok へのサインインを案内し、最初のものがデフォルトエージェントになります。その後は、パネルはすべてのサブスクリプションを 1 ページに表示します：各エージェントとアカウントとそのプラン、5 時間セッションと週次制限のそれぞれのメーターとリセットまでの時間（ホバーすると正確なパーセンテージが表示されます）、または残りの前払い残高が、今週のトークンや最も使ったモデルなど、すべての利用状況を順に表示する行の下にあります。_Make something_ の下では、新しいテーマ、プラグイン、アプリのスタータープロンプトを提供し、タスクをデフォルトエージェントに渡します。アプリは Omarchy 自身の Hype、Monologue、Omacut と同じように、C++ と Qt Quick で、omarchy-app エージェントスキルに従って構築され、必要なコンパイラと Qt の要素はインストール済みで提供されます。Claude Code、Codex、Grok、Fireworks は箱から出してすぐに対応しています。

バーアイコンを左クリックでパネル、右クリックでデフォルトエージェントを起動します。その背後の使用記録は 15 分ごとに `omarchy agent usage-update` によって再生成され、パネルは同期フォルダ経由で他のマシンからの使用状況をマージすることさえできます。完全な設定は `$OMARCHY_PATH/shell/plugins/agents/` の下の README を参照してください。

### 複数のサブスクリプション

例えば個人用の Max と仕事用のもののように、Claude、Codex、Grok のプランを複数支払っている場合、Omarchy はすべてをサインインしたままにして、その間を移動できます。エージェントパネルの + でサブスクリプションを追加するとその場で案内してくれるか、`omarchy agent account add claude Work`（または `codex`、または `grok`）で追加してください。CLI がなければインストールします。プロバイダーの最初のアカウントは、CLI がいつも見る場所で、通常のブラウザからサインインします。それ以降のすべてのアカウントはプライベートウィンドウからサインインするので、ブラウザがすでにサインインしているアカウントが誤って選ばれることはありません。追加するアカウントとしてそこでサインインし、すでに開いていたプライベートウィンドウは先に閉じてください。これのために CLI からログアウトしてはいけません：ログアウトすると保存されたサインインが取り消され、そのアカウントを再び追加しなければならなくなります。

プロバイダーごとに 1 つのアカウントがアクティブで、すべての新しいセッションはそのアカウントとして始まります：`cx`、`cy`、素の `claude`、`codex`、`grok`、`omarchy agent` 経由で起動したもの、`PATH` 上で CLI を見つけるスクリプトやエディタです。`omarchy agent account use work` で切り替え（`omarchy agent account use main` で戻る）、またはパネルでアカウントの番号を押してから `Enter` を押す（またはその Use ボタンをクリックする）ことで切り替えてください。すでに実行中のセッションは、開始したアカウントのままです。会話履歴、設定、スキル、プラグインはアカウント間で共有されるので、同じフォルダで `claude --continue` を実行すると、新しいアカウントで中断したところから再開できます。

複数のアカウントがあると、パネルは各アカウントの制限を横並びに表示し、アクティブなものがマークされます。デフォルトでは、アクティブなアカウントが制限の 95% を超えると Omarchy が通知し、通知をクリックすると最も余裕のあるアカウントに切り替わります。パネルでアカウント行にホバーし、Use の横に表示される Autoswitch をクリックする（または `m` を押す）か、`omarchy agent account mode auto` を実行すると、代わりに自動で切り替わります。オンの間は Autoswitch が Use の場所を取り、再びクリックすると通知に戻ります。`omarchy agent account mode auto 90` のように数字を追加して閾値を変更してください。すべてのアカウントが閾値を超えている場合、そのことを 1 回だけ聞き、どのアカウントが最初に空くかも知らされます。アクティブなアカウントが閾値の 15 ポイント以内にある間（デフォルトでは 80%）、その制限は 15 分ごとではなく 3 分ごとにチェックされます。

`omarchy agent account list` はすべてのアカウントとその最新の制限を表示し、`omarchy agent account remove work` は 1 つを忘れ、`omarchy agent account rename primary Hey` は 1 つの名前を変更します（またはパネルでアカウント名をクリックします）。これらのコマンドはデフォルトエージェントのアカウントに対して動作します。別のプロバイダーに届くには、`omarchy agent account use codex side` のように最初に名前を付けてください。`~/.claude` や `~/.codex` にすでにあったログインは _Main_ アカウントで、ある場所に留まります。約 8 時間以上使われていないアカウントは _Sign-in required_ と表示されることがあります。それをクリックしてパネル内でそのアカウントにもう一度サインインするか、そのアカウントでセッションを開始すると、サインインが自動的にリフレッシュされます。アカウント追加時に持っていた MCP サーバーはそのアカウントについてきますが、後で `claude mcp add` で追加したものは、追加したアカウントにしか届きません。Claude Desktop や CLI バイナリへの絶対パスで設定されたツールは切り替えに追従しません。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`GROK_HOME` は選択されたアカウントより優先されます。

### クラッシュ診断

Omarchy は systemd-coredump でプロセスクラッシュを監視します。何かがセグメンテーションフォルトすると「Process crashed」通知が届きます。それをクリックすると、クラッシュは Omarchy の diagnose-crash スキルとともにデフォルトエージェントに渡され、エージェントがコアダンプから事実を確立し、そのクラッシュが upstream への報告に値するか判断する手順を案内します。`coredumpctl list` の任意の PID に対して `omarchy agent crash <pid>` で手動でも実行できます。

監視はデフォルトでオンです。_実行 > トグル > クラッシュキャプチャ_ の下で（または `omarchy toggle crash-capture` で）オフにすると通知は止まります。`omarchy agent crash <pid>` は引き続き手動で動作します。

クラッシュはプログラムごとにもサイレンスでき、それが診断の最後に提案されることです。`omarchy crash mute hyprland` はそのプログラムだけの通知を止め、`omarchy crash mute hyprland off` は戻し、`omarchy crash mute` を単独で実行するとミュートしたものが一覧表示されます。バイナリのパスでも名前でも同じように受け付けるので、`omarchy crash mute /usr/bin/hyprland` でも同じことが起きます。スペースを含む名前は `omarchy crash mute 'Some App'` のように引用してください。他のすべては引き続き通知し、ミュートされたプログラムは引き続きクラッシュします。これはリマインダーを隠すもので、何かを修正するものではありません。

### デスクトップアプリ

_インストール > AI_ メニューにはいくつかのグラフィカルな AI アプリもあります：ChatGPT デスクトップアプリ、Claude デスクトップアプリ（Chat、Cowork、Claude Code タブ付きの Anthropic の Linux ベータ）、xAI のモデルとチャットするための Grok Bot、Hermes Desktop、OpenClaw、Perplexity デスクトップアプリです。Grok Bot はデスクトップチャットアプリです。コーディングエージェントは `grok` コマンドです。

Hermes Desktop は知っておくべきものです。なぜならマシンには 1 つの Hermes しかなく、それはアプリのものだからです：Hermes はアプリ経由でのみインストールされ、デフォルトエージェントが実行する `hermes` コマンドはアプリのものです。Hermes をデフォルトエージェントとして選ぶと、_インストール > AI_ エントリと同じものがインストールされます：パッケージと、Hermes 自身のインストーラーによって `~/.hermes` の下にセットアップされる Hermes ランタイムで、初めてのときは数分かかります。そのランタイムはターミナルの `hermes` コマンド、デフォルトエージェント、アプリがすべて使う 1 つの Hermes で、Omarchy リリースを待つのではなく `hermes update` で自分で更新します。インストールすると、Hermes に Omarchy テーマが `omarchy` という名前のスキンとして渡され、テーマを切り替えるたびにすべての Hermes の表面が追従します。そうしたくなければ、Hermes の Appearance 設定の下か `/skin` で別のものを選んでください。Omarchy はその選択に干渉しません。_削除 > AI_ の下でアプリを削除すると、まずゲートウェイを含めて Hermes が閉じられ、そのランタイムも一緒に持っていき、別途指示しない限り、チャット、メモリ、Hermes が自分のために書いたスキルは保持されます：そのデータと接続設定も一緒に消すべきか、デフォルトは「いいえ」で尋ねます。

OpenClaw のデスクトップ体験はその Control UI で、独自のローカルゲートウェイをバックエンドとする Web アプリとして開きます。OpenClaw は `~/.openclaw` に住み、自分で更新します：Control UI の「Update Gateway」ボタンを使うか `openclaw update` を実行すると、ゲートウェイが新しいバージョンで再起動します。Omarchy は新規インストールが始まるリリースを選ぶだけです。_削除 > AI_ の下で OpenClaw を削除すると、ゲートウェイサービスとアプリが一緒に持っていかれ、その後 `~/.openclaw` も消すべきか尋ねます。そこには OpenClaw 自身やダウンロードしたプラグインランタイムと並んでチャットや資格情報が入っているからです。デフォルトは保持であり、OpenClaw を再びインストールするとそれを再び取り込みます。

### ローカル LLM

Omarchy はローカル LLM モデルを実行する 2 つの方法を推奨します：LM Studio と Ollama です。LM Studio はオープンウェイトモデルを見つけ、インストールし、実行するための GUI インターフェースを提供します。簡単に始めるのに最適な方法です。Ollama は同様のことを行う CLI を提供します。でもローカルモデルが初めてなら、LM Studio から始めることをお勧めします。どちらも Omarchy メニューの _インストール > AI_ の下でインストールできます。

### Omarchy スキル

エージェントスキルは、AI が特定のツールを特定の方法で使う助けとなり、Omarchy にはシステムを調整するためのデフォルトスキルが同梱されています。Hyprland 設定の微調整、バーの調整、ゼロからの新しいテーマ作成のようなことです。Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`）、そして汎用の `~/.agents/skills` の場所のスキルディレクトリにシンボリックリンクされているので、ほとんどのハーネスが自動的に取り込みます。

しかし、このスキルは実験的なものとして扱うべきです。モデルによって効果は異なります。まずはプランモードで実行し、エージェントが何を変更したいか把握するのが最善です。そして、エージェントがすべてをめちゃくちゃにした場合に備えて、変更をロールバックしたり、`omarchy reinstall configs` を呼び出したりする準備をしておいてください。
