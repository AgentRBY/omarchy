# IA

O Omarchy trata os agentes de programação com IA como cidadãos de primeira classe, mas não escolhe um favorito por ti. Em vez disso, todas as principais CLIs de agentes de programação vêm pré-ligadas como um lançador de carregamento preguiçoso. Os lançadores são pequenos stubs geridos pelo [mise](https://mise.jdx.dev/) em `~/.local/bin/`, por isso nada é transferido até à primeira vez que realmente executares um. O Hermes é a exceção: não há nenhum stub para ele, e escolhê-lo instala o Hermes Desktop, como _Aplicações de ambiente de trabalho_ abaixo explica. Invoca qualquer um destes e autentica-te quando for pedido:

| Comando    | Agente                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) da xAI                        |
| `pi`       | [Pi do Mario Zechner](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), o arnês da OpenRouter |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), o agente da Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai), o agente de programação da Meta           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

O `ori` é o caso estranho: corre os outros arneses contra todo o catálogo de modelos da OpenRouter, por isso `ori claude`, `ori codex` ou `ori opencode` arrancam esses agentes em qualquer modelo para que os apontes, e `ori code` é o próprio agente do Ori.

Para integrares uma CLI adicional da mesma forma, executa `omarchy-mise-install <pacote> [nome-do-comando]`. Os stubs mantêm-se atualizados juntamente com tudo o resto que o mise gere quando executas `omarchy update` (ou o alias `mup`).

O `grok` instala-se através do pacote `grok` próprio do mise, tal como o `claude` e o `codex`. Executa `grok`, ou escolhe-o em _Configurar > Predefinições > Agente_. Salta o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, coloca-a à frente no `PATH` e sobrescreve o invólucro do Omarchy.

### O agente predefinido

Escolhe o teu agente predefinido com `omarchy default agent <nome>` ou em _Configurar > Predefinições > Agente_ no menu do Omarchy (`Super + Space`). Se o agente ainda não estiver instalado, escolhê-lo instala-o primeiro. Um Omarchy acabado de instalar vai convidar-te a fazeres essa escolha com uma notificação única.

Escolher o Claude também tenta configurar a sua extensão de browser para o Chromium, o Chrome, o Brave, o Brave Origin e o Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a tua palavra-passe do sistema; cancelar ou uma instalação de extensão falhada continua a selecionar e a lançar o Claude. Reinicia o browser, ativa a extensão se for pedido e inicia sessão no Claude para terminar a ligação. Executa `/chrome` no Claude para verificares a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era a tua predefinição antes de esta configuração ser adicionada, seleciona-o outra vez para instalares a extensão.

O [Muse Code](https://dev.meta.ai) — o `muse` da Meta — usa um stub do mise pré-instalado, tal como os outros agentes. Escolhê-lo como predefinição instala o lançador oficial da Meta através do backend HTTP do mise. O lançador verifica e atualiza o binário nativo para a tua máquina.

Depois de teres escolhido, `Super + Shift + Ctrl + A` lança o agente predefinido numa janela de terminal dedicada (ou apresenta o seletor se ainda não tiveres escolhido). Também o podes lançar diretamente numa tarefa com `omarchy agent prompt "Review this project"`. Os agentes lançados desta forma correm sem supervisão nos seus respetivos modos de não-parar-para-perguntar, por isso prepara-te para que eles façam realmente coisas! E uma vez que os agentes se recusam a memorizar a confiança para o teu diretório pessoal, os lançamentos a partir de `$HOME` arrancam antes em `~/Work`.

Também há atalhos de terminal: `a` executa o agente predefinido em linha no terminal atual, enquanto `c`, `cx` e `cy` arrancam diretamente o OpenCode, o Claude Code e o Codex (outra vez nos seus modos de aprovação automática). As mudanças de tema também se sincronizam com os agentes: o Claude Code, o Pi, o OpenCode e o Hermes (assim que o Omarchy o tiver instalado) acompanham todos quando mudas o tema do Omarchy.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de teres configurado um agente, o seu painel guia-te pelo início de sessão no Claude, no Codex ou no Grok, e o primeiro torna-se o teu agente predefinido. Depois disso, o painel coloca todas as subscrições numa única página: cada agente e conta com o seu plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanais, com o tempo que falta para a reposição (passa o cursor por cima para veres a percentagem exata), ou o saldo pré-pago restante, por baixo de uma linha que roda por aquilo que utilizaste em todas elas, como os tokens desta semana e o teu modelo mais usado. Em _Fazer alguma coisa_ oferece prompts iniciais para um novo tema, plugin ou aplicação que entregam a tarefa ao teu agente predefinido. As aplicações são construídas da forma como são as próprias aplicações do Omarchy, o Hype, o Monologue e o Omacut, em C++ e Qt Quick, seguindo a skill de agente omarchy-app, e o compilador e as peças de Qt de que elas precisam vêm instalados. O Claude Code, o Codex, o Grok e o Fireworks estão cobertos à saída da caixa.

Clica com o botão esquerdo no ícone da barra para o painel, e com o botão direito para lançares o teu agente predefinido. Os registos de utilização por trás dele são regenerados a cada 15 minutos pelo `omarchy agent usage-update`, e o painel consegue até fundir a utilização das tuas outras máquinas através de uma pasta sincronizada. Vê o README em `$OMARCHY_PATH/shell/plugins/agents/` para as definições completas.
### Várias subscrições

Se pagares mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo — o Omarchy consegue manter todos ligados e circular entre eles. Adiciona uma subscrição com o + no painel de agentes, que te guia aí mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Instala a CLI se ela estiver em falta. A primeira conta de um fornecedor inicia sessão através do teu browser normal, mesmo onde a CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o teu browser já está ligado não seja apanhada por engano; inicia sessão aí como a conta que estás a adicionar e fecha primeiro qualquer janela privada que já tenhas aberto. Nunca termines sessão na CLI para fazeres isto: terminar sessão revoga o início de sessão guardado, e essa conta teria de ser adicionada outra vez.

Uma conta por fornecedor está ativa, e cada nova sessão arranca como ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, qualquer coisa lançada através do `omarchy agent`, e scripts ou editores que encontrem a CLI no `PATH`. Muda com `omarchy agent account use work` (e volta com `omarchy agent account use main`), ou no painel, premindo o número de uma conta e depois `Enter` (ou clicando no seu botão Utilizar). As sessões que já estão a correr mantêm-se na conta com que arrancaram. O histórico de conversas, as definições, as skills e os plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta retoma onde paraste na nova conta.

Com mais do que uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa assinalada. Por predefinição, o Omarchy notifica-te quando a conta ativa ultrapassa 95% de um limite, e clicar na notificação muda para a conta com mais folga. Passa o cursor sobre a linha de uma conta no painel e clica em Comutação automática, que aparece ao lado de Utilizar (ou prime `m`), ou executa `omarchy agent account mode auto`, para que ele mude sozinho; enquanto estiver ligado, Comutação automática toma o lugar de Utilizar, e clicar nele outra vez volta a notificar. Adiciona um número para mudares o limiar, como em `omarchy agent account mode auto 90`. Se todas as contas estiverem acima do limiar, vais ouvir falar disso uma vez, juntamente com a conta que se liberta primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limiar (80% na predefinição), os seus limites são verificados a cada três minutos em vez de a cada 15.

`omarchy agent account list` mostra todas as contas e os seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` muda o nome de uma (ou clica no nome de uma conta no painel). Estes comandos atuam nas contas do teu agente predefinido; para chegares ao outro fornecedor, nomeia-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinhas em `~/.claude` ou em `~/.codex` é a conta _Principal_ e fica onde está. Uma conta deixada por utilizar por mais de cerca de oito horas pode mostrar _Início de sessão necessário_; clica nela para voltares a iniciar sessão nessa conta mesmo no painel, ou arranca uma sessão nela, o que refresca o início de sessão por si só. Os servidores MCP que tinhas quando uma conta foi adicionada acompanham-na, mas aqueles que adicionares depois com `claude mcp add` só chegam à conta em que os adicionaste. O Claude Desktop e as ferramentas configuradas com um caminho absoluto para um binário de CLI não seguem a mudança. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de falhas

O Omarchy observa o systemd-coredump à procura de falhas de processos. Quando alguma coisa faz segfault, recebes uma notificação "Processo falhou" — clica nela e a falha é entregue ao teu agente predefinido juntamente com a skill diagnose-crash do Omarchy, que guia o agente no estabelecimento dos factos a partir do despejo de memória e na decisão sobre se vale a pena reportar a falha a montante. Também a podes executar à mão contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A observação está ligada por predefinição. Desliga-a em _Acionar > Alternar > Captura de falhas_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` continua a funcionar à mão.

As falhas também podem ser silenciadas programa a programa, que é aquilo que o diagnóstico te oferece no fim. `omarchy crash mute hyprland` para as notificações só desse programa, `omarchy crash mute hyprland off` traz-las de volta, e `omarchy crash mute` sozinho lista aquilo que silenciaste. Aceita o caminho do binário tão bem quanto o seu nome, por isso `omarchy crash mute /usr/bin/hyprland` faz a mesma coisa. Coloca entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a notificar, e o programa silenciado continua a falhar — isto esconde o lembrete, não corrige nada.

### Aplicações de ambiente de trabalho

O menu _Instalar > IA_ também traz algumas aplicações gráficas de IA: a aplicação de ambiente de trabalho do ChatGPT, a aplicação de ambiente de trabalho do Claude (a beta para Linux da Anthropic, com separadores Chat, Cowork e Claude Code), o Grok Bot para conversares com os modelos da xAI, o Hermes Desktop, o OpenClaw e a aplicação de ambiente de trabalho do Perplexity. O Grok Bot é a aplicação de chat de ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é aquele sobre o qual vale a pena saber, porque uma máquina tem um só Hermes, e ele é o da aplicação: o Hermes só alguma vez é instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala a mesma coisa que a entrada de _Instalar > IA_: o pacote e um tempo de execução do Hermes em `~/.hermes` configurado pelo próprio instalador do Hermes, o que demora alguns minutos da primeira vez. Esse tempo de execução é o único Hermes que o comando `hermes` do terminal, o agente predefinido e a aplicação usam todos, e atualiza-se a si próprio com `hermes update`, em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema do Omarchy como uma skin chamada `omarchy`, que todas as superfícies do Hermes acompanham quando mudas de tema; escolhe outra nas definições de Aspeto do Hermes ou com `/skin` se preferires que não o faça, e o Omarchy deixa essa escolha em paz. Remover a aplicação em _Remover > IA_ fecha primeiro o Hermes, gateway incluída, leva consigo esse tempo de execução e mantém as tuas conversas, as memórias e as skills que o Hermes escreveu para si próprio, a menos que lhe digas o contrário: pergunta, com a predefinição no não, se esses dados e as tuas definições de ligação também devem ir embora.

A experiência de ambiente de trabalho do OpenClaw é a sua Interface de Controlo, que abre como uma aplicação web apoiada pela sua própria gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: usa o botão "Atualizar Gateway" da Interface de Controlo ou executa `openclaw update`, e a gateway reinicia na nova versão. O Omarchy escolhe apenas a versão a partir da qual uma instalação nova arranca. Remover o OpenClaw em _Remover > IA_ leva consigo o serviço da gateway e a aplicação e depois pergunta se `~/.openclaw` também deve ir embora, uma vez que isso guarda as tuas conversas e credenciais juntamente com o próprio OpenClaw e os tempos de execução de plugins que ele transfere; a predefinição mantém-no, e instalar outra vez o OpenClaw volta a apanhá-lo.

### LLMs locais

O Omarchy recomenda duas formas de correr modelos LLM locais: o LM Studio e o Ollama. O LM Studio fornece uma interface gráfica para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de arrancar facilmente. O Ollama oferece uma CLI para fazer o mesmo. Mas se és novo nos modelos locais, eu começaria pelo LM Studio. Podes instalar qualquer um deles em _Instalar > IA_ no menu do Omarchy.

### A Skill do Omarchy

As skills de agente ajudam a IA a usar ferramentas específicas de uma forma específica, e o Omarchy vem com uma skill predefinida para adaptares o sistema. Como afinar a tua configuração do Hyprland, ajustar a barra, ou até criar um novo tema a partir do zero. Está ligada por symlink aos diretórios de skills do Claude Code (`~/.claude/skills`), do Codex (`~/.codex/skills`), do Pi (`~/.pi/agent/skills`), do Antigravity (`~/.gemini/config/skills`), do Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`) e à localização genérica `~/.agents/skills`, de forma que a maioria dos arneses a apanha automaticamente.

Mas deves tratar esta skill como experimental. Modelos diferentes vão usá-la com efeitos diferentes. É melhor correr primeiro em modo de plano, para teres uma ideia daquilo que o agente gostaria de mudar. E depois estares pronto para reverter as alterações ou até invocar `omarchy reinstall configs`, se o agente fizer uma confusão com tudo.
