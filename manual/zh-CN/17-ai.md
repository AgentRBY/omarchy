# AI

Omarchy 将 AI 编程智能体视为一等公民，但它不会替你选一个最爱。相反，每个主要的编程智能体 CLI 都预先接线为懒加载启动器。这些启动器是 `~/.local/bin/` 中由 [mise](https://mise.jdx.dev/) 管理的微型存根，因此在你实际第一次运行之前不会下载任何内容。Hermes 是个例外：没有为它提供存根，选择它会安装 Hermes Desktop，如下文_桌面应用_所解释的那样。调用其中任何一个，并在提示时进行身份验证：

| 命令    | 智能体                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) from xAI                        |
| `pi`       | [Mario Zechner's Pi](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), OpenRouter's harness |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), Nous Research's agent  |
| `muse`     | [Muse Code](https://dev.meta.ai), Meta's coding agent           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` 是个例外：它针对 OpenRouter 的整个模型目录运行其他工具，所以 `ori claude`、`ori codex` 或 `ori opencode` 会在你所指向的任何模型上启动这些智能体，而 `ori code` 是 Ori 自己的智能体。

要以相同方式包装其他 CLI，请运行 `omarchy-mise-install <package> [command-name]`。当你运行 `omarchy update`（或 `mup` 别名）时，这些存根会连同 mise 管理的其他所有内容一起保持最新。

`grok` 通过 mise 的第一方 `grok` 包安装，与 `claude` 和 `codex` 的方式相同。运行 `grok`，或在_设置 > 默认项 > 智能体_下选择它。跳过 x.ai 上的 `curl | bash` 安装程序。那条路径会在 `~/.grok/bin` 中放第二份副本，将其前置到 `PATH` 上，并覆盖 Omarchy 的包装器。

### 默认智能体

用 `omarchy default agent <name>` 或在 Omarchy 菜单（`Super + Space`）的_设置 > 默认项 > 智能体_下选择你的默认智能体。如果智能体尚未安装，选择它会先安装它。全新的 Omarchy 会通过一次性通知邀请你进行此选择。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置其浏览器扩展。扩展设置适用于所有用户，可能会要求你的系统密码；取消或扩展安装失败仍会选择并启动 Claude。重启你的浏览器，如果提示则启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 检查连接。Firefox 和 Zen 不支持此扩展。如果在此设置添加之前 Claude 已经是你的默认项，请再次选择它以安装扩展。

[Muse Code](https://dev.meta.ai)——Meta 的 `muse`——和其他智能体一样使用预装的 mise 存根。将其选为默认项会通过 mise 的 HTTP 后端安装 Meta 的官方启动器。该启动器会验证并更新适用于你机器的原生二进制文件。

选择后，`Super + Shift + Ctrl + A` 会在专用终端窗口中启动默认智能体（或者，如果你尚未选择，则调出选择器）。你也可以用 `omarchy agent prompt "Review this project"` 直接将其启动到任务中。以这种方式启动的智能体会以各自“不要停下来询问”的模式无人值守地运行，所以要准备好它们真的会做事情！而且由于智能体拒绝记住对你的主目录的信任，从 `$HOME` 启动的会转而在 `~/Work` 中启动。

也有终端快捷方式：`a` 在当前终端内联运行默认智能体，而 `c`、`cx` 和 `cy` 直接启动 OpenCode、Claude Code 和 Codex（同样以自动批准模式）。主题更改也会同步到智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 安装了它）都会跟随。

### 智能体面板

菜单栏有一个智能体图标。在你设置智能体之前，其面板会引导你登录 Claude、Codex 或 Grok，第一个会成为你的默认智能体。在此之后，该面板将每个订阅放在一页上：每个智能体和帐户及其计划、每个 5 小时会话和每周限制的计量表以及重置前的时间（将鼠标悬停以查看确切百分比），或剩余的预付余额，在一行文字之下，该文字循环显示你在所有这些上的使用情况，例如本周的词元和你最常用的模型。在_生成一些内容_下，它提供新主题、插件或应用的入门提示，这些提示将任务交给你的默认智能体。应用的构建方式与 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，并遵循 omarchy-app 智能体技能，它们需要的编译器和 Qt 组件都已安装。Claude Code、Codex、Grok 和 Fireworks 开箱即受支持。

左键单击栏图标打开面板，右键单击启动你的默认智能体。其背后的使用记录每 15 分钟由 `omarchy agent usage-update` 重新生成，该面板甚至可以通过同步文件夹合并来自其他机器的使用情况。有关完整设置，请参见 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你为多个 Claude、Codex 或 Grok 计划付费——比如一个个人 Max 和一个工作用的——Omarchy 可以让它们全部保持登录，并在它们之间切换。使用智能体面板中的 + 添加订阅，它会当场引导你完成，或者使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果 CLI 缺失，它会安装它。某提供商的第一个帐户通过你的普通浏览器登录，就在 CLI 始终查找的位置。之后的每一个都通过隐私窗口登录，这样你浏览器中已登录的帐户就不会被误选；在那里以你要添加的帐户登录，并先关闭你已打开的任何隐私窗口。切勿为此退出 CLI 登录：退出会吊销已保存的登录，该帐户就必须再次添加。

每个提供商有一个活动帐户，每个新会话都以该帐户开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何内容，以及在 `PATH` 上找到 CLI 的脚本或编辑器。用 `omarchy agent account use work` 切换（再用 `omarchy agent account use main` 切换回来），或者在面板中按某帐户的编号然后按 `Enter`（或单击其“使用”按钮）。已在运行的会话会保持它们开始时使用的帐户。对话历史、设置、技能和插件在帐户之间共享，因此在同一文件夹中使用 `claude --continue` 可在新帐户上接续你离开的地方。

当有多个帐户时，面板会并排显示每个帐户的限制，并标记活动的那个。默认情况下，当活动帐户超过某项限制的 95% 时，Omarchy 会通知你，单击通知会切换到余量最多的帐户。将鼠标悬停在面板中某帐户行上，单击“使用”旁边出现的“自动切换”（或按 `m`），或运行 `omarchy agent account mode auto`，可使其自行切换；当它打开时，“自动切换”取代“使用”，再次单击它则回到通知方式。添加一个数字以更改阈值，例如 `omarchy agent account mode auto 90`。如果每个帐户都超过了阈值，你只会收到一次通知，并会得知哪个帐户最先释放。当活动帐户在其阈值 15 个百分点以内（默认值为 80%）时，其限制每三分钟检查一次，而不是每 15 分钟检查一次。

`omarchy agent account list` 显示每个帐户及其最新限制，`omarchy agent account remove work` 忘记一个帐户，`omarchy agent account rename primary Hey` 重命名一个帐户（或者单击面板中某帐户的名称）。这些命令对你默认智能体的帐户起作用；要访问其他提供商，请先命名它，例如 `omarchy agent account use codex side`。你在 `~/.claude` 或 `~/.codex` 中已有的登录是_主_帐户，并保持在原位。未使用超过约八小时的帐户可能显示_需要登录_；单击它可在面板中直接让该帐户重新登录，或者在其中启动一个会话，这会自行刷新登录。当某个帐户添加时你拥有的 MCP 服务器会随之而来，但你稍后用 `claude mcp add` 添加的服务器只会到达你添加它们时使用的帐户。Claude Desktop 和配置了 CLI 二进制绝对路径的工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于选定的帐户。

### 崩溃诊断

Omarchy 会监视 systemd-coredump 以检测进程崩溃。当某个程序发生段错误时，你会收到“进程崩溃”通知——单击它，崩溃信息就会连同 Omarchy 的 diagnose-crash 技能一起交给你的默认智能体，该技能会引导智能体从核心转储中确定事实，并决定该崩溃是否值得报告给上游。你也可以用 `omarchy agent crash <pid>` 手动针对 `coredumpctl list` 中的任何 PID 运行它。

该监视默认打开。在_触发 > 开关 > 崩溃捕获_下关闭它（或用 `omarchy toggle crash-capture`），通知就会停止；`omarchy agent crash <pid>` 仍可手动使用。

崩溃也可以按程序逐个静默，这正是诊断在最后向你提供的功能。`omarchy crash mute hyprland` 仅停止该程序的通知，`omarchy crash mute hyprland off` 将其恢复，单独的 `omarchy crash mute` 列出你已静默的内容。它既接受二进制文件的路径，也接受其名称，所以 `omarchy crash mute /usr/bin/hyprland` 作用相同。将带有空格的名称用引号括起来，例如 `omarchy crash mute 'Some App'`。其他所有程序仍会发出通知，被静默的程序仍会崩溃——这只是隐藏了提醒，并没有修复任何东西。

### 桌面应用

_安装 > AI_ 菜单还包含一些图形 AI 应用：ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux 测试版，带有 Chat、Cowork 和 Claude Code 选项卡）、用于与 xAI 模型聊天的 Grok Bot、Hermes Desktop、OpenClaw 和 Perplexity 桌面应用。Grok Bot 是桌面聊天应用。编程智能体是 `grok` 命令。

Hermes Desktop 是需要了解的一个，因为一台机器只有一个 Hermes，而且它是该应用的那个：Hermes 只能通过该应用安装，默认智能体运行的 `hermes` 命令就是该应用的那个。选择 Hermes 作为默认智能体，安装的是与_安装 > AI_ 条目相同的东西：该软件包，以及由 Hermes 自己的安装程序设置在 `~/.hermes` 下的 Hermes 运行时，第一次需要几分钟。该运行时是终端 `hermes` 命令、默认智能体和应用共同使用的唯一 Hermes，它通过 `hermes update` 自行更新，而不是等待 Omarchy 版本。安装它还会将 Omarchy 主题交给 Hermes，作为名为 `omarchy` 的皮肤，每个 Hermes 界面在你切换主题时都会跟随；如果你不希望如此，请在 Hermes 的外观设置下或用 `/skin` 选择另一个，Omarchy 不会干涉这一选择。在_移除 > AI_下移除该应用会先关闭 Hermes（包括网关），带走该运行时，并保留你的聊天、记忆和 Hermes 为自己编写的技能，除非你另有指示：它会询问（默认否）是否也应删除这些数据和你的连接设置。

OpenClaw 的桌面体验是其 Control UI，它作为由自己本地网关支持的 Web 应用打开。OpenClaw 位于 `~/.openclaw` 并自行更新：使用 Control UI 的“更新网关”按钮或运行 `openclaw update`，网关会在新版本上重启。Omarchy 只选择全新安装的起始版本。在_移除 > AI_下移除 OpenClaw 会带走网关服务和应用，然后询问 `~/.openclaw` 是否也应删除，因为那里面有你的聊天和凭据，以及 OpenClaw 本身和它下载的插件运行时；默认会保留它，再次安装 OpenClaw 会重新拾取它。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供 GUI 界面，用于查找开放权重模型、安装它们并运行它们。这是轻松入门的好方法。Ollama 提供类似的 CLI。但如果你是本地模型新手，我建议从 LM Studio 开始。你可以在 Omarchy 菜单的_安装 > AI_下安装任一个。

### Omarchy 技能

智能体技能帮助 AI 以特定方式使用特定工具，Omarchy 附带了一个用于定制系统的默认技能。例如调整你的 Hyprland 配置、调节栏，甚至从头创建一个新主题。它被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每个 `~/.hermes/profiles/*/skills`）的技能目录，以及通用的 `~/.agents/skills` 位置，因此大多数工具都会自动拾取它。

但你应将此技能视为实验性的。不同的模型会以不同的效果使用它。最好先在计划模式下运行，这样你就能了解智能体想更改什么。然后准备好回滚更改，甚至在智能体把一切搞得一团糟时调用 `omarchy reinstall configs`。
