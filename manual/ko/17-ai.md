# AI

Omarchy는 AI 코딩 에이전트를 일등 시민으로 취급하지만, 여러분을 위해 어떤 것을 좋아할지를 고르지는 않습니다. 대신 모든 주요 코딩 에이전트 CLI가 레이지 로딩되는 실행기로 미리 연결되어 있습니다. 실행기는 `~/.local/bin/`에 있는 [mise](https://mise.jdx.dev/) 관리 스텁으로, 작아서 실제로 실행하기 전까지는 아무것도 다운로드되지 않습니다. Hermes는 예외입니다. 이를 위한 스텁은 없으며, 선택하면 아래의 _데스크톱 앱_에서 설명하는 것처럼 Hermes Desktop이 설치됩니다. 이 중 어느 것이든 호출하고 메시지가 표시되면 인증하세요:

| 명령    | 에이전트                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | xAI의 [Grok Build](https://x.ai/build)                        |
| `pi`       | [Mario Zechner의 Pi](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), OpenRouter의 하네스 |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), Nous Research의 에이전트  |
| `muse`     | [Muse Code](https://dev.meta.ai), Meta의 코딩 에이전트           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori`는 약간 다릅니다. 다른 하네스를 OpenRouter의 전체 모델 카탈로그에 대해 실행합니다. 따라서 `ori claude`, `ori codex`, 또는 `ori opencode`는 여러분이 지정하는 어떤 모델에서든 해당 에이전트를 시작하고, `ori code`는 Ori 자체의 에이전트입니다.

추가 CLI를 같은 방식으로 감싸려면 `omarchy-mise-install <package> [command-name]`를 실행하세요. 이 스텁은 `omarchy update`(또는 `mup` 별칭)를 실행할 때 mise가 관리하는 다른 모든 것과 함께 최신 상태로 유지됩니다.

`grok`은 `claude` 및 `codex`와 같은 방식으로 mise의 자체 `grok` 패키지를 통해 설치됩니다. `grok`을 실행하거나, _설정 > 기본값 > 에이전트_에서 선택하세요. x.ai의 `curl | bash` 설치 프로그램은 사용하지 마세요. 그 경로는 `~/.grok/bin`에 두 번째 복사본을 넣고, PATH 앞에 추가하며, Omarchy의 래퍼(wrapper)를 덮어씁니다.

### 기본 에이전트

기본 에이전트는 `omarchy default agent <name>` 또는 Omarchy 메뉴(`Super + Space`)의 _설정 > 기본값 > 에이전트_에서 선택하세요. 에이전트가 아직 설치되지 않았다면, 선택하면 먼저 설치합니다. 새로 설치한 Omarchy는 일회성 알림으로 이 선택을 제안합니다.

Claude를 선택하면 Chromium, Chrome, Brave, Brave Origin, Edge용 브라우저 확장도 함께 설정하려고 시도합니다. 확장 설정은 모든 사용자에게 적용되며 시스템 비밀번호를 요구할 수 있습니다. 취소하거나 확장 설치에 실패해도 Claude는 여전히 선택되고 실행됩니다. 브라우저를 재시작하고, 메시지가 표시되면 확장을 활성화한 뒤, Claude에 로그인하여 연결을 마무리하세요. 연결을 확인하려면 Claude에서 `/chrome`을 실행하세요. Firefox와 Zen은 이 확장을 지원하지 않습니다. 이 설정이 추가되기 전에 이미 Claude를 기본값으로 쓰고 있었다면, 확장을 설치하기 위해 다시 선택하세요.

[Muse Code](https://dev.meta.ai) — Meta의 `muse` — 는 다른 에이전트처럼 사전 설치된 mise 스텁을 사용합니다. 이를 기본값으로 선택하면 mise의 HTTP 백엔드를 통해 Meta의 공식 실행기를 설치합니다. 실행기가 여러분의 머신에 맞는 네이티브 바이너리를 확인하고 업데이트합니다.

선택한 뒤에는 `Super + Shift + Ctrl + A`가 전용 터미널 창에서 기본 에이전트를 실행합니다(아직 선택하지 않았다면 선택기가 나타납니다). `omarchy agent prompt "Review this project"`처럼 바로 작업에 투입할 수도 있습니다. 이렇게 실행된 에이전트는 각자의 "묻지 않고 계속" 모드에서 무인으로 실행되므로, 실제로 일을 할 각오를 하세요! 그리고 에이전트들은 여러분의 홈 디렉터리에 대한 신뢰(trust)를 기억하지 않으므로, `$HOME`에서 실행하면 대신 `~/Work`에서 시작합니다.

터미널 단축키도 있습니다: `a`는 현재 터미널 안에서 기본 에이전트를 인라인으로 실행하고, `c`, `cx`, `cy`는 OpenCode, Claude Code, Codex를 직접 시작합니다(역시 자동 승인(auto-approving) 모드에서). 테마 변경도 에이전트와 동기화됩니다: Claude Code, Pi, OpenCode, 그리고 Hermes(Omarchy가 설치한 뒤)는 모두 Omarchy 테마를 바꿀 때 함께 따라갑니다.

### 에이전트 패널

상단 바에는 에이전트 아이콘이 있습니다. 에이전트를 설정하기 전에는 이 패널이 Claude, Codex, 또는 Grok에 로그인하도록 안내하고, 첫 번째로 로그인한 것이 기본 에이전트가 됩니다. 그 뒤에는 이 패널이 모든 구독을 한 페이지에 담습니다: 각 에이전트와 계정의 요금제, 5시간 세션 제한과 주간 제한 각각에 대한 미터와 재설정까지 남은 시간(정확한 백분율은 마우스를 올리면 표시됩니다), 또는 남은 선불 잔액, 그리고 이번 주 토큰 사용량과 가장 많이 쓴 모델처럼 모든 구독에 걸쳐 사용한 내용을 순환하며 보여 주는 줄이 함께 제공됩니다. _무언가 만들기(Make something)_ 아래에서는 새 테마, 플러그인, 또는 앱을 만들어 기본 에이전트에 작업을 넘기는 시작 프롬프트를 제공합니다. 앱은 Omarchy 자체의 Hype, Monologue, Omacut처럼 C++와 Qt Quick으로 만들어지며, omarchy-app 에이전트 스킬을 따르고, 필요한 컴파일러와 Qt 조각들이 함께 설치됩니다. Claude Code, Codex, Grok, Fireworks는 기본 상태로 지원됩니다.

바 아이콘을 왼쪽 클릭하면 패널이 열리고, 오른쪽 클릭하면 기본 에이전트가 실행됩니다. 그 뒤를 받치는 사용량 기록은 `omarchy agent usage-update`를 통해 15분마다 재생성되며, 패널은 동기화된 폴더를 통해 다른 머신의 사용량까지 병합할 수 있습니다. 전체 설정은 `$OMARCHY_PATH/shell/plugins/agents/` 아래의 README를 참조하세요.

### 여러 구독

Claude, Codex, 또는 Grok 요금제를 두 개 이상 구독하고 있다면 — 예를 들어 개인 Max 하나와 업무용 하나 — Omarchy는 모두 로그인 상태로 유지하고 그 사이를 오갈 수 있습니다. 에이전트 패널의 + 로 구독을 추가하세요. 그 자리에서 안내가 따로 있습니다. 또는 `omarchy agent account add claude Work`(또는 `codex`, 또는 `grok`)로 추가하세요. CLI가 없으면 설치합니다. 공급자의 첫 번째 계정은 CLI가 항상 보는 바로 그곳에서 평소 브라우저를 통해 로그인합니다. 그 뒤의 모든 계정은 비공개 창의 로그인으로 들어가므로, 브라우저에 이미 로그인된 계정이 실수로 채택되지 않습니다. 거기서 추가하려는 계정으로 로그인하고, 이미 열어 둔 비공개 창이 있다면 먼저 닫으세요. 이를 위해 CLI에서 로그아웃하면 절대 안 됩니다: 로그아웃하면 저장된 로그인이 취소되고, 그 계정은 다시 추가해야 합니다.

공급자당 하나의 계정이 활성화되며, 모든 새 세션은 그 계정으로 시작합니다: `cx`, `cy`, 일반 `claude`, `codex`, 또는 `grok`, `omarchy agent`를 통해 실행되는 모든 것, 그리고 PATH에서 CLI를 찾는 스크립트나 편집기가 그 예입니다. `omarchy agent account use work`(그리고 `omarchy agent account use main`으로 다시 돌아가기)로 전환하거나, 패널에서 계정의 번호를 누른 뒤 `Enter`를 누르세요(또는 Use 버튼을 클릭하세요). 이미 실행 중인 세션은 시작한 계정에 남아 있습니다. 대화 기록, 설정, 스킬, 플러그인은 계정 간에 공유되므로, 같은 폴더에서 `claude --continue`를 실행하면 새 계정에서 중단했던 지점부터 계속 진행합니다.

계정이 두 개 이상이면 패널은 각 계정의 제한을 나란히 보여 주며, 활성 계정이 표시됩니다. 기본적으로 Omarchy는 활성 계정이 제한의 95%를 넘으면 알려 주고, 알림을 클릭하면 가장 여유가 있는 계정으로 전환합니다. 패널에서 계정 줄에 마우스를 올리고 Use 옆에 나타나는 자동 전환(Autoswitch)을 클릭하거나(또는 `m`을 누르거나), `omarchy agent account mode auto`를 실행하면 대신 자동으로 전환합니다. 켜져 있는 동안은 자동 전환이 Use를 대체하고, 다시 클릭하면 알림 상태로 돌아갑니다. `omarchy agent account mode auto 90`처럼 숫자를 추가해 임계값을 변경할 수 있습니다. 모든 계정이 임계값을 넘으면 어느 계정이 먼저 비는지와 함께 한 번만 알려 줍니다. 활성 계정이 임계값으로부터 15포인트 이내에 있는 동안(기본값에서는 80%)에는 15분마다가 아니라 3분마다 제한을 검사합니다.

`omarchy agent account list`는 모든 계정과 그 최신 제한을 보여 주고, `omarchy agent account remove work`는 하나를 잊어버리며, `omarchy agent account rename primary Hey`는 이름 하나를 바꿉니다(또는 패널에서 계정의 이름을 클릭하세요). 이 명령들은 기본 에이전트의 계정에 작동합니다. 다른 공급자에게 접근하려면 먼저 이름을 지정하세요. 예를 들어 `omarchy agent account use codex side`처럼요. `~/.claude`나 `~/.codex`에 이미 갖고 있던 로그인은 _Main_ 계정으로 그대로 남습니다. 약 8시간 이상 사용하지 않은 계정은 _로그인 필요(Sign-in required)_를 표시할 수 있습니다. 패널에서 클릭해 바로 그 계정에 다시 로그인하거나, 그 계정에서 세션을 시작하면 로그인이 자동으로 새로고침됩니다. 계정이 추가되었을 때 갖고 있던 MCP 서버는 그 계정으로 따라오지만, 나중에 `claude mcp add`로 추가한 서버는 추가한 계정에서만 접근할 수 있습니다. Claude Desktop과 CLI 바이너리의 절대 경로로 구성된 도구는 전환을 따르지 않습니다. 명시적인 `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, 또는 `GROK_HOME`이 선택된 계정보다 우선합니다.

### 충돌 진단

Omarchy는 systemd-coredump를 통해 프로세스 충돌을 감시합니다. 어떤 것이 세그폴트(segfault)하면 "Process crashed" 알림을 받게 됩니다 — 클릭하면, 충돌이 Omarchy의 diagnose-crash 스킬과 함께 기본 에이전트에게 넘어갑니다. 이 스킬은 핵심 덤프(core dump)에서 사실을 확립하고 충돌이 상위에 보고할 가치가 있는지를 에이전트에게 안내합니다. `coredumpctl list`의 모든 PID에 대해 `omarchy agent crash <pid>`를 직접 실행할 수도 있습니다.

감시는 기본적으로 켜져 있습니다. _실행 > 토글 > 충돌 캡처_(또는 `omarchy toggle crash-capture`)에서 끄면 알림이 중단됩니다. `omarchy agent crash <pid>`는 여전히 직접 실행할 수 있습니다.

충돌은 프로그램 단위로 무음 처리할 수도 있으며, 진단 끝에 제안하는 것도 이것입니다. `omarchy crash mute hyprland`는 해당 프로그램에 대한 알림만 중단하고, `omarchy crash mute hyprland off`는 다시 복원하며, 단독으로 `omarchy crash mute`를 실행하면 무음 처리한 목록이 나옵니다. 바이너리의 경로도 이름만큼 즐겁게 받아들이므로 `omarchy crash mute /usr/bin/hyprland`도 같은 일을 합니다. 공백이 있는 이름은 `omarchy crash mute 'Some App'`처럼 따옴표로 묶으세요. 다른 모든 것은 여전히 알림을 보내며, 무음 처리된 프로그램은 여전히 충돌합니다 — 이는 리마인더를 숨길 뿐 아무것도 고치지 않습니다.

### 데스크톱 앱

_설치 > AI_ 메뉴에는 그래픽 AI 앱도 몇 가지 있습니다: ChatGPT 데스크톱 앱, Claude 데스크톱 앱(Anthropic의 Linux 베타, Chat, Cowork, Claude Code 탭 포함), xAI 모델과 채팅하기 위한 Grok Bot, Hermes Desktop, OpenClaw, 그리고 Perplexity 데스크톱 앱입니다. Grok Bot은 데스크톱 채팅 앱입니다. 코딩 에이전트는 `grok` 명령입니다.

Hermes Desktop은 알아 둘 가치가 있습니다. 머신마다 Hermes가 하나만 있고, 그 Hermes는 앱의 것이기 때문입니다: Hermes는 오직 앱을 통해서만 설치되며, 기본 에이전트가 실행하는 `hermes` 명령은 앱의 것입니다. Hermes를 기본 에이전트로 선택하면 _설치 > AI_ 항목이 설치하는 것과 같은 것이 설치됩니다: 패키지, 그리고 Hermes 자체 설치 프로그램에 의해 `~/.hermes` 아래에 설정되는 Hermes 런타임으로, 처음에는 몇 분이 걸립니다. 그 런타임은 터미널 `hermes` 명령, 기본 에이전트, 앱이 모두 사용하는 단 하나의 Hermes이며, Omarchy 릴리스를 기다리지 않고 `hermes update`로 스스로 업데이트합니다. 이를 설치하면 Hermes에 Omarchy 테마를 `omarchy`라는 이름의 스킨으로도 전달하게 되며, 모든 Hermes 화면이 테마를 바꿀 때 따라갑니다. 원하지 않으면 Hermes의 모양(Appearance) 설정에서 또는 `/skin`으로 다른 것을 선택하세요. 그러면 Omarchy는 그 선택을 그대로 둡니다. _제거 > AI_에서 앱을 제거하면 게이트웨이를 포함해 Hermes를 먼저 닫고, 그 런타임을 함께 가져가며, 별도로 지시하지 않는 한 여러분의 채팅, 메모리, 그리고 Hermes가 자신을 위해 직접 쓴 스킬은 남깁니다: 그런 데이터와 연결 설정도 함께 사라져야 하는지를 묻는데, 기본값은 아니오입니다.

OpenClaw의 데스크톱 경험은 Control UI로, 자체 로컬 게이트웨이를 백엔드로 한 웹 앱으로 열립니다. OpenClaw는 `~/.openclaw`에 살고 있으며, 스스로를 업데이트합니다: Control UI의 "Update Gateway" 버튼을 사용하거나 `openclaw update`를 실행하면 게이트웨이가 신 버전으로 재시작합니다. Omarchy는 새로 설치한 경우가 시작할 릴리스만 선택합니다. _제거 > AI_에서 OpenClaw를 제거하면 게이트웨이 서비스와 앱을 함께 가져가고, 그 뒤 `~/.openclaw`도 사라져야 하는지를 묻습니다. 이는 채팅과 자격 증명을 OpenClaw 자체와, 그것이 다운로드하는 플러그인 런타임까지 함께 보유하고 있기 때문입니다. 기본값은 남기는 것이고, OpenClaw를 다시 설치하면 이를 다시 받아들입니다.

### 로컬 LLM

Omarchy는 로컬 LLM 모델을 실행하는 두 가지 방법을 추천합니다: LM Studio와 Ollama입니다. LM Studio는 오픈 웨이트 모델을 찾고, 설치하고, 실행하기 위한 GUI 인터페이스를 제공합니다. 쉽게 시작하는 훌륭한 방법입니다. Ollama는 비슷하게 이를 수행하는 CLI를 제공합니다. 하지만 로컬 모델이 처음이라면 LM Studio로 시작하길 권합니다. Omarchy 메뉴의 _설치 > AI_에서 둘 중 하나를 설치할 수 있습니다.

### Omarchy 스킬

에이전트 스킬은 AI가 특정 도구를 특정 방식으로 쓰도록 돕고, Omarchy는 시스템을 조정하기 위한 기본 스킬과 함께 제공됩니다. Hyprland 구성을 다듬고, 바를 조정하거나, 처음부터 새 테마를 만드는 것 같은 작업이 해당합니다. Claude Code(`~/.claude/skills`), Codex(`~/.codex/skills`), Pi(`~/.pi/agent/skills`), Antigravity(`~/.gemini/config/skills`), Hermes(`~/.hermes/skills`와 각 `~/.hermes/profiles/*/skills`), 그리고 일반적인 `~/.agents/skills` 위치 등, 대부분의 하네스가 자동으로 가져가는 스킬 디렉터리에 심링크가 걸려 있습니다.

하지만 이 스킬은 실험적인 것으로 취급해야 합니다. 서로 다른 모델은 서로 다르게 사용합니다. 먼저 계획 모드에서 실행하여 에이전트가 무엇을 바꾸고 싶어 하는지 파악하는 것이 가장 좋습니다. 그리고 에이전트가 모든 것을 엉망으로 만든다면, 변경을 롤백하거나 심지어 `omarchy reinstall configs`를 실행할 준비를 하세요.
