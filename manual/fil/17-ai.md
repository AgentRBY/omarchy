# AI

Itinuturing ng Omarchy ang mga AI coding agent bilang mga first-class citizen, ngunit hindi ito pumipili ng paborito para sa iyo. Sa halip, ang bawat pangunahing coding-agent CLI ay dumadating na paunang naka-wire bilang isang lazy-loaded na launcher. Ang mga launcher ay maliliit na [mise](https://mise.jdx.dev/)-managed na stub sa `~/.local/bin/`, kaya walang mada-download hanggang sa unang pagkakataong patakbuhin mo ang isa. Ang Hermes ang eksepsyon: walang naka-stub para dito, at ang pagpili dito ay nag-i-install ng Hermes Desktop, tulad ng ipinaliliwanag ng _Mga desktop app_ sa ibaba. Tawagin ang alinman sa mga ito at mag-authenticate kapag sinenyasan:

| Command    | Agent                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) mula sa xAI                        |
| `pi`       | [Pi ni Mario Zechner](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), ang harness ng OpenRouter |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), ang agent ng Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai), ang coding agent ng Meta           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

Ang `ori` ang kakaiba: pinapatakbo nito ang iba pang mga harness laban sa buong katalogo ng modelo ng OpenRouter, kaya ang `ori claude`, `ori codex`, o `ori opencode` ay nagsisimula sa mga agent na iyon sa anumang modelong ituturo mo sa kanila, at ang `ori code` ay ang sariling agent ng Ori.

Para i-wrap ang isang karagdagang CLI sa parehong paraan, patakbuhin ang `omarchy-mise-install <package> [command-name]`. Ang mga stub ay pinapanatiling napapanahon kasama ng lahat ng iba pang pinamamahalaan ng mise kapag pinapatakbo mo ang `omarchy update` (o ang alias na `mup`).

Ang `grok` ay ini-install sa pamamagitan ng first-party na `grok` package ng mise, sa parehong paraan tulad ng `claude` at `codex`. Patakbuhin ang `grok`, o piliin ito sa ilalim ng _Pag-setup > Mga Default > Agent_. Laktawan ang `curl | bash` installer sa x.ai. Ang path na iyon ay naglalagay ng pangalawang kopya sa `~/.grok/bin`, inilalagay ito sa unahan ng `PATH`, at papatungan ang wrapper ng Omarchy.

### Ang default na agent

Piliin ang iyong default na agent gamit ang `omarchy default agent <name>` o sa ilalim ng _Pag-setup > Mga Default > Agent_ sa Menu ng Omarchy (`Super + Space`). Kung hindi pa naka-install ang agent, ang pagpili dito ay ini-install muna ito. Aanyayahan ka ng isang bagong Omarchy na gawin ang pagpipiliang ito gamit ang isang one-time na notipikasyon.

Ang pagpili sa Claude ay sumusubok ding i-setup ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Ang setup ng extension ay nalalapat sa lahat ng user at maaaring humingi ng iyong system password; ang pagkansela o isang nabigong pag-install ng extension ay pipili at maglulunsad pa rin ng Claude. I-restart ang iyong browser, i-enable ang extension kung sinenyasan, at mag-sign in sa Claude para tapusin ang pagkonekta nito. Patakbuhin ang `/chrome` sa Claude para suriin ang koneksyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung ang Claude na ang iyong default bago idinagdag ang setup na ito, piliin ito ulit para i-install ang extension.

Ang [Muse Code](https://dev.meta.ai) — ang `muse` ng Meta — ay gumagamit ng isang paunang naka-install na mise stub tulad ng iba pang mga agent. Ang pagpili dito bilang default ay nag-i-install ng opisyal na launcher ng Meta sa pamamagitan ng HTTP backend ng mise. Bine-verify at ina-update ng launcher ang native binary para sa iyong makina.

Kapag nakapili ka na, inilulunsad ng `Super + Shift + Ctrl + A` ang default na agent sa isang nakalaang bintana ng terminal (o inilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad nang diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Ang mga agent na inilunsad sa ganitong paraan ay tumatakbo nang walang nagbabantay sa kani-kanilang mga mode na don't-stop-to-ask, kaya maging handa na talagang may gawin sila! At dahil tumatanggi ang mga agent na tandaan ang tiwala para sa iyong home directory, ang mga paglulunsad mula sa `$HOME` ay nagsisimula sa `~/Work` sa halip.

Mayroon ding mga shortcut sa terminal: pinapatakbo ng `a` ang default na agent nang inline sa kasalukuyang terminal, habang sinisimulan ng `c`, `cx`, at `cy` ang OpenCode, Claude Code, at Codex nang diretso (muli sa kanilang mga mode na auto-approving). Nagsi-sync din ang mga pagbabago ng tema sa mga agent: ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) ay lahat sumusunod kapag lumipat ka ng tema ng Omarchy.

### Ang panel ng mga agent

Ang top bar ay may icon ng mga agent. Bago ka mag-setup ng isang agent, ginagabayan ka ng panel nito sa pag-sign in sa Claude, Codex, o Grok, at ang una ay magiging iyong default na agent. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa isang pahina: bawat agent at account kasama ang plano nito, isang meter para sa bawat isa sa 5-hour session at weekly limit nito kasama ang oras hanggang mag-reset ito (i-hover para sa eksaktong porsyento), o ang natitirang prepaid balance, sa ilalim ng isang linya na umiikot sa kung ano ang nagamit mo sa kabuuan ng lahat ng mga ito, tulad ng mga token ngayong linggo at ang iyong pinakaginagamit na modelo. Sa ilalim ng _Make something_ nag-aalok ito ng mga starter prompt para sa isang bagong tema, plugin, o app na nagbibigay ng gawain sa iyong default na agent. Ang mga app ay binuo sa paraan ng sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-app agent skill, at ang compiler at mga piraso ng Qt na kailangan nila ay naka-install na. Ang Claude Code, Codex, Grok, at Fireworks ay sakop mula sa simula.

I-left-click ang icon ng bar para sa panel, i-right-click para ilunsad ang iyong default na agent. Ang mga tala ng paggamit sa likod nito ay muling nabubuo tuwing 15 minuto ng `omarchy agent usage-update`, at maaari pang pagsamahin ng panel ang paggamit mula sa iyong iba pang mga makina sa pamamagitan ng isang naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong mga setting.

### Maraming subscription

Kung nagbabayad ka para sa higit sa isang plano ng Claude, Codex, o Grok — isang personal na Max at isa para sa trabaho, halimbawa — maaari silang panatilihin ng Omarchy na lahat naka-sign in at lumipat sa pagitan ng mga ito. Magdagdag ng subscription gamit ang + sa panel ng mga agent, na gagabay sa iyo roon mismo, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nag-sign in sa pamamagitan ng iyong normal na browser, doon mismo kung saan palaging tumitingin ang CLI. Ang bawat isa pagkatapos niyon ay nag-sign in sa pamamagitan ng isang private window, kaya ang account na naka-sign in na ang iyong browser ay hindi makukuha nang hindi sinasadya; mag-sign in doon bilang ang account na idinaragdag mo, at isara muna ang anumang private window na nabuksan mo na. Huwag kailanman mag-log out sa CLI para gawin ito: ang pag-log out ay nagrerevoke ng na-save na sign-in, at ang account na iyon ay kailangang idagdag ulit.

Isang account bawat provider ang aktibo, at ang bawat bagong session ay nagsisimula bilang ito: `cx`, `cy`, isang plain na `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap ng CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos ang `Enter` (o pag-click sa Use button nito). Ang mga session na tumatakbo na ay nananatili sa account na sinimulan nila. Ang kasaysayan ng pag-uusap, mga setting, skill, at plugin ay ibinabahagi sa mga account, kaya ang `claude --continue` sa parehong folder ay nagpapatuloy kung saan ka tumigil sa bagong account.

Kapag may higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na minarkahan ang aktibo. Bilang default, inaabisuhan ka ng Omarchy kapag lumampas ang aktibong account sa 95% ng isang limit, at ang pag-click sa notipikasyon ay lumilipat sa account na may pinakamalaking headroom. I-hover ang linya ng isang account sa panel at i-click ang Autoswitch na lumalabas sa tabi ng Use (o pindutin ang `m`), o patakbuhin ang `omarchy agent account mode auto`, para lumipat ito nang mag-isa sa halip; habang naka-on ito, pumapalit ang Autoswitch sa Use, at ang pag-click ulit dito ay bumabalik sa pag-aabiso. Magdagdag ng numero para baguhin ang threshold, tulad ng sa `omarchy agent account mode auto 90`. Kung ang bawat account ay lampas sa threshold, maririnig mo tungkol dito nang isang beses, kasama kung aling account ang unang magiging libre. Habang ang isang aktibong account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), ang mga limit nito ay sinusuri tuwing tatlong minuto sa halip na tuwing 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong mga limit nito, kinakalimutan ng `omarchy agent account remove work` ang isa, at pinapalitan ng pangalan ng `omarchy agent account rename primary Hey` ang isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga command na ito sa mga account ng iyong default na agent; para maabot ang ibang provider, pangalanan ito muna, tulad ng sa `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ na account at nananatili kung nasaan ito. Ang isang account na hindi nagamit nang higit sa humigit-kumulang walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito para muling i-sign in ang account na iyon mismo sa panel, o magsimula ng isang session dito, na nagre-refresh ng sign-in nang mag-isa. Ang mga MCP server na mayroon ka noong idinagdag ang isang account ay sumasama dito, ngunit ang mga idinaragdag mo mamaya gamit ang `claude mcp add` ay umaabot lang sa account kung saan mo idinagdag ang mga ito. Ang Claude Desktop at mga tool na naka-configure na may absolute path papunta sa isang CLI binary ay hindi sumusunod sa paglipat. Ang isang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` ay nangingibabaw sa napiling account.

### Pagsusuri ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga crash ng proseso. Kapag may nag-segfault, makakakuha ka ng isang "Process crashed" na notipikasyon — i-click ito, at ang crash ay ibibigay sa iyong default na agent kasama ang diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung ang crash ay sulit iulat upstream. Maaari mo rin itong patakbuhin nang mano-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Ang pagbabantay ay naka-on bilang default. I-off ito sa ilalim ng _Mag-trigger > I-toggle > Pagsagap ng Crash_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notipikasyon; gumagana pa rin nang mano-mano ang `omarchy agent crash <pid>`.

Ang mga crash ay maaari ring patahimikin nang isa-isa bawat programa, na siyang iaalok sa iyo ng diagnosis sa dulo. Pinahihinto ng `omarchy crash mute hyprland` ang mga notipikasyon para sa programang iyon lang, ibinabalik sila ng `omarchy crash mute hyprland off`, at inililista ng `omarchy crash mute` nang mag-isa kung ano ang na-mute mo. Tumatanggap ito ng path ng binary nang kasing saya ng pangalan nito, kaya ginagawa ng `omarchy crash mute /usr/bin/hyprland` ang parehong bagay. I-quote ang isang pangalan na may puwang, tulad ng sa `omarchy crash mute 'Some App'`. Lahat ng iba pa ay nag-aabiso pa rin, at ang na-mute na programa ay nag-crash pa rin — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

Ang menu na _I-install > AI_ ay may dala ring ilang graphical na AI app: ang ChatGPT desktop app, ang Claude desktop app (ang Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para sa pakikipag-chat sa mga modelo ng xAI, Hermes Desktop, OpenClaw, at ang Perplexity desktop app. Ang Grok Bot ang desktop chat app. Ang coding agent ay ang `grok` command.

Ang Hermes Desktop ang dapat malaman, dahil ang isang makina ay may isang Hermes, at ito ay sa app: ang Hermes ay ini-install lang kailanman sa pamamagitan ng app, at ang `hermes` command na pinapatakbo ng default na agent ay sa app. Ang pagpili sa Hermes bilang default na agent ay nag-i-install ng parehong bagay na ginagawa ng entry na _I-install > AI_: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na na-setup ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang nag-iisang Hermes na ginagamit ng terminal na `hermes` command, ng default na agent at ng app, at ina-update nito ang sarili nito gamit ang `hermes update` sa halip na maghintay ng isang release ng Omarchy. Ang pag-install dito ay nagbibigay din sa Hermes ng tema ng Omarchy bilang isang skin na pinangalanang `omarchy`, na sinusundan ng bawat Hermes surface habang lumilipat ka ng mga tema; pumili ng iba sa ilalim ng mga setting ng Appearance ng Hermes o gamit ang `/skin` kung mas gusto mong hindi, at hahayaan ng Omarchy ang pagpipiliang iyon. Ang pag-alis sa app sa ilalim ng _Alisin > AI_ ay isinasara muna ang Hermes, kasama ang gateway, inaalis ang runtime na iyon kasama nito, at pinapanatili ang iyong mga chat, alaala, at ang mga skill na isinulat ng Hermes para sa sarili nito maliban kung sasabihin mong hindi: nagtatanong ito, na may default na hindi, kung ang data na iyon at ang iyong mga setting ng koneksyon ay dapat ding mawala.

Ang karanasan sa desktop ng OpenClaw ay ang Control UI nito, na bumubukas bilang isang web app na sinusuportahan ng sarili nitong local gateway. Ang OpenClaw ay nakatira sa `~/.openclaw` at ina-update ang sarili nito: gamitin ang "Update Gateway" button ng Control UI o patakbuhin ang `openclaw update`, at ang gateway ay muling magsisimula sa bagong bersyon. Pinipili lang ng Omarchy ang release kung saan magsisimula ang isang bagong pag-install. Ang pag-alis sa OpenClaw sa ilalim ng _Alisin > AI_ ay inaalis ang serbisyo ng gateway at ang app kasama nito at pagkatapos ay nagtatanong kung ang `~/.openclaw` ay dapat ding mawala, dahil hawak niyon ang iyong mga chat at credential kasama ng OpenClaw mismo at ng mga plugin runtime na dina-download nito; pinapanatili ito ng default, at ang muling pag-install ng OpenClaw ay kukunin itong muli.

### Mga Lokal na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga lokal na LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng isang GUI interface para sa paghahanap ng mga open-weight model, pag-install sa mga ito, at pagpapatakbo sa mga ito. Isa itong mahusay na paraan para makapagsimula nang madali. Nag-aalok ang Ollama ng isang CLI para gawin ito nang katulad. Ngunit kung bago ka sa mga lokal na modelo, magsisimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _I-install > AI_ sa Menu ng Omarchy.

### Ang Omarchy Skill

Tinutulungan ng mga agent skill ang AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at ang Omarchy ay ipinapadala na may isang default na skill para sa pag-aayos ng sistema. Tulad ng pag-tweak ng iyong Hyprland config, pagsasaayos ng bar, o kahit paglikha ng isang bagong tema mula sa simula. Naka-symlink ito sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyon na `~/.agents/skills`, kaya karamihan sa mga harness ay awtomatikong kinukuha ito.

Ngunit dapat mong ituring ang skill na ito bilang eksperimental. Gagamitin ito ng iba't ibang modelo sa iba't ibang epekto. Pinakamainam na tumakbo muna sa plan mode, para magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handa na i-rollback ang mga pagbabago o kahit tawagan ang `omarchy reinstall configs`, kung magulo ng agent ang lahat.
