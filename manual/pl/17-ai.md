# AI

Omarchy traktuje agentów kodujących AI jako obywateli pierwszej klasy, ale nie wybiera za ciebie ulubionego. Zamiast tego każdy duży CLI agenta kodującego jest wstępnie podłączony jako leniwie ładowany uruchamiacz. Uruchamiacze to małe, zarządzane przez [mise](https://mise.jdx.dev/) stuby w `~/.local/bin/`, więc nic nie jest pobierane, dopóki faktycznie któregoś nie uruchomisz. Hermes jest wyjątkiem: dla niego nie ma stuba, a wybranie go instaluje Hermes Desktop, jak wyjaśnia niżej _Aplikacje pulpitu_. Wywołaj którykolwiek z nich i uwierzytelnij się na żądanie:

| Polecenie    | Agent                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) od xAI                        |
| `pi`       | [Pi Mario Zechnera](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), osprzęt OpenRouter |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), agent Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai), agent kodujący Meta           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` jest wyjątkiem: uruchamia pozostałe osprzęty na katalogu modeli OpenRoutera, więc `ori claude`, `ori codex` albo `ori opencode` startują tych agentów na modelu, który wskażesz, a `ori code` to własny agent Ori.

Aby opakować dodatkowe CLI w ten sam sposób, uruchom `omarchy-mise-install <package> [command-name]`. Stuby są utrzymywane w aktualności wraz z wszystkim, czym mise zarządza, gdy uruchamiasz `omarchy update` (albo alias `mup`).

`grok` jest instalowany przez pierwszą paczkę `grok` mise, tak samo jak `claude` i `codex`. Uruchom `grok` albo wybierz go pod _Ustawienia > Domyślne > Agent_. Pomiń instalator `curl | bash` na x.ai. Ta ścieżka umieszcza drugą kopię w `~/.grok/bin`, wstawia ją przed pozostałymi na `PATH` i nadpisuje opakowanie Omarchy.

### Domyślny agent

Swojego domyślnego agenta wybierasz przez `omarchy default agent <name>` albo pod _Ustawienia > Domyślne > Agent_ w menu Omarchy (`Super + Space`). Jeśli agent nie jest jeszcze zainstalowany, wybranie go najpierw go zainstaluje. Świeże Omarchy zaprosi cię do dokonania tego wyboru jednorazowym powiadomieniem.

Wybranie Claude próbuje też skonfigurować jego rozszerzenie przeglądarkowe dla Chromium, Chrome, Brave, Brave Origin oraz Edge. Konfiguracja rozszerzenia dotyczy wszystkich użytkowników i może poprosić o twoje hasło systemowe; anulowanie albo nieudana instalacja rozszerzenia nadal wybiera i uruchamia Claude. Restartuj przeglądarkę, włącz rozszerzenie, jeśli będzie o to poproszone, i zaloguj się do Claude, żeby dopinać połączenie. Uruchom `/chrome` w Claude, żeby sprawdzić połączenie. Firefox i Zen nie obsługują tego rozszerzenia. Jeśli Claude był już twoim domyślnym, zanim dodano tę konfigurację, wybierz go ponownie, żeby zainstalować rozszerzenie.

[Muse Code](https://dev.meta.ai) — `muse` od Meta — używa preinstalowanego stuba mise jak inni agenci. Wybranie go jako domyślnego instaluje oficjalny uruchamiacz Meta przez backend HTTP mise. Uruchamiacz weryfikuje i aktualizuje natywny plik binarny dla twojej maszyny.

Gdy już wybierzesz, `Super + Shift + Ctrl + A` uruchamia domyślnego agenta w dedykowanym oknie terminala (albo pokazuje selektor, jeśli jeszcze nie wybrałeś). Możesz też uruchomić go od razu do zadania przez `omarchy agent prompt "Review this project"`. Agenci uruchamiani w ten sposób działają bez nadzoru, w ich trybach "nie zatrzymuj się, żeby zapytać", więc bądź gotowy na to, że faktycznie zrobią parę rzeczy! A ponieważ agenci odmawiają zapamiętania zaufania dla katalogu domowego, uruchomienia z `$HOME` startują zamiast tego w `~/Work`.

Są też skróty terminalowe: `a` uruchamia domyślnego agenta w bieżącym terminalu, natomiast `c`, `cx` i `cy` startują OpenCode, Claude Code i Codex bezpośrednio (ponownie w ich trybach autoakceptacji). Zmiany motywu też synchronizują się dla agentów: Claude Code, Pi, OpenCode oraz Hermes (gdy Omarchy go już zainstaluje) podążają za zmianą motywu Omarchy.

### Panel agentów

Górny pasek ma ikonę agentów. Zanim skonfigurujesz agenta, jej panel przeprowadza cię przez logowanie się do Claude, Codex lub Grok, a pierwszy z nich staje się twoim domyślnym agentem. Potem panel umieszcza każdą subskrypcję na jednej stronie: każdy agent i konto z ich planem, wskaźnik dla każdego spośród limitów sesji 5 godzin i limitów tygodniowych wraz z czasem pozostałym do zresetowania (najedź, aby zobaczyć dokładny procent) albo pozostałe przedpłacone saldo, pod wierszem, który przechodzi rotacyjnie przez to, co użyłeś we wszystkich z nich, jak tokeny w tym tygodniu i twój najczęściej używany model. Pod _Zrób coś_ oferuje startowe prompty dla nowego motywu, wtyczki lub aplikacji, które przekazują zadanie twojemu domyślnemu agentowi. Aplikacje zbudowane są tak jak własne Hype, Monologue i Omacut Omarchy, w C++ oraz Qt Quick, zgodnie z umiejętnością agenta omarchy-app, a kompilator i potrzebne im kawałki Qt są zainstalowane. Od razu pokryte są Claude Code, Codex, Grok i Fireworks.

Lewy klik na ikonę paska otwiera panel, prawy klik uruchamia twojego domyślnego agenta. Zapisy zużycia za panelem są generowane co 15 minut przez `omarchy agent usage-update`, a panel może nawet łączyć zużycie z innych twoich maszyn przez zsynchronizowany folder. Pełne ustawienia znajdziesz w README pod `$OMARCHY_PATH/shell/plugins/agents/`.

### Kilka subskrypcji

Jeśli płacisz za więcej niż jeden plan Claude, Codex lub Grok — na przykład osobisty Max i służbowy — Omarchy może trzymać je wszystkie zalogowane i przemieszczasz się między nimi. Dodasz subskrypcję przez + w panelu agentów, który przeprowadzi cię przez to na miejscu, albo przez `omarchy agent account add claude Work` (albo `codex`, albo `grok`). Zainstaluje CLI, jeśli go brakuje. Pierwsze konto dla dostawcy loguje się przez twoją zwykłą przeglądarkę, dokładnie tam, gdzie CLI zawsze patrzy. Każde kolejne loguje się przez okno prywatne, żeby konto, w którym przeglądarka już jest zalogowana, nie zostało przez pomyłkę przejęte; zaloguj się tam jako konto, które dodajesz, i najpierw zamknij każde prywatne okno, które miałeś już otwarte. Nigdy nie wylogowuj się z CLI, żeby to zrobić: wylogowanie odwołuje zapisane logowanie, a to konto musiałoby zostać dodane ponownie.

Jedno konto per dostawca jest aktywne i każda nowa sesja zaczyna się od niego: `cx`, `cy`, zwykłe `claude`, `codex` albo `grok`, wszystko uruchomione przez `omarchy agent` oraz skrypty lub edytory, które znajdują CLI na `PATH`. Przełączaj się przez `omarchy agent account use work` (i z powrotem przez `omarchy agent account use main`) albo w panelu, naciskając numer konta, a potem `Enter` (albo klikając jego przycisk Use). Sesje, które już działają, pozostają na koncie, od którego zaczęły. Historia rozmów, ustawienia, umiejętności i wtyczki są współdzielone między kontami, więc `claude --continue` w tym samym folderze kontynuuje na nowym koncie tam, gdzie skończyłeś.

Przy więcej niż jednym koncie panel pokazuje limity każdego konta obok siebie, z zaznaczonym aktywnym. domyślnie Omarchy powiadamia cię, gdy aktywne konto przekroczy 95% limitu, a kliknięcie powiadomienia przełącza je na konto z największym zapasem. Najedź na wiersz konta w panelu i kliknij Autoswitch, który pojawia się obok Use (albo naciśnij `m`), albo uruchom `omarchy agent account mode auto`, żeby przełączał się sam; gdy jest włączony, Autoswitch zajmuje miejsce Use, a ponowne kliknięcie wraca do powiadamiania. Dodaj liczbę, żeby zmienić próg, jak w `omarchy agent account mode auto 90`. Jeśli każde konto przekracza próg, dostaniesz o tym wiadomość raz, wraz z tym, które konto zwalnia się pierwsze. Gdy aktywne konto jest w odległości 15 punktów od swojego progu (80% przy wartości domyślnej), jego limity są sprawdzane co trzy minuty, a nie co 15.

`omarchy agent account list` pokazuje każde konto i jego najnowsze limity, `omarchy agent account remove work` zapomina jedno, a `omarchy agent account rename primary Hey` zmienia nazwę jednego (albo kliknij nazwę konta w panelu). Polecenia te działają na konta twojego domyślnego agenta; aby sięgnąć drugiego dostawcy, nazwij go najpierw, jak w `omarchy agent account use codex side`. Logowanie, które już miałeś w `~/.claude` lub `~/.codex`, to konto _Main_ i pozostaje tam, gdzie jest. Konto pozostawione nieużywane dłużej niż około osiem godzin może pokazać _Wymagane logowanie_; kliknij je, żeby ponownie zalogować się na to konto od razu w panelu, albo uruchom w nim sesję, co samo odświeży logowanie. Serwery MCP, które miałeś, gdy konto było dodawane, trafiają do niego, ale te, które dodasz później przez `claude mcp add`, docierają tylko na konto, na którym je dodałeś. Claude Desktop i narzędzia skonfigurowane ze ścieżką bezwzględną do pliku binarnego CLI nie podążają za przełączeniem. Jawne `CLAUDE_CONFIG_DIR`, `CODEX_HOME` albo `GROK_HOME` ma pierwszeństwo względem wybranego konta.

### Diagnozowanie awarii

Omarchy obserwuje systemd-coredump pod kątem awarii procesów. Gdy coś trafia na segfault, dostaniesz powiadomienie "Process crashed" — kliknij je, a awaria jest przekazywana twojemu domyślnemu agentowi wraz z umiejętnością diagnose-crash Omarchy, która przeprowadza agenta przez ustalanie faktów ze zrzutu rdzenia oraz decydowanie, czy awaria jest warta zgłoszenia upstream. Możesz też uruchomić to ręcznie dla dowolnego PID-a z `coredumpctl list` przez `omarchy agent crash <pid>`.

Obserwacja jest domyślnie włączona. Wyłącz ją pod _Akcje > Przełącz > Rejestr awarii_ (albo przez `omarchy toggle crash-capture`), a powiadomienia ustaną; `omarchy agent crash <pid>` nadal działa ręcznie.

Awarie można też wyciszać po jednym programie na raz — to właśnie oferuje ci diagnoza na końcu. `omarchy crash mute hyprland` zatrzymuje powiadomienia tylko dla tego programu, `omarchy crash mute hyprland off` je przywraca, a `omarchy crash mute` samo listuje to, co wyciszyłeś. Przyjmuje równie chętnie ścieżkę pliku binarnego jak jego nazwę, więc `omarchy crash mute /usr/bin/hyprland` robi to samo. Wycinek nazwy ze spacją, na przykład `omarchy crash mute 'Some App'`. Wszystko inne nadal powiadamia, a wyciszony program nadal ulega awarii — to ukrywa przypomnienie, niczego nie naprawia.

### Aplikacje pulpitu

Menu _Instaluj > AI_ mieści też kilka graficznych aplikacji AI: aplikację pulpitową ChatGPT, aplikację pulpitową Claude (beta Anthropic na Linuksa, z kartami Chat, Cowork i Claude Code), Grok Bot do rozmawiania z modelami xAI, Hermes Desktop, OpenClaw oraz aplikację pulpitową Perplexity. Grok Bot to aplikacja pulpitowa do czatu. Agentem kodującym jest polecenie `grok`.

Hermes Desktop to ten, którego warto znać, bo maszyna ma jeden Hermes i należy on do aplikacji: Hermes instaluje się wyłącznie przez aplikację, a polecenie `hermes`, które uruchamia domyślny agent, należy do aplikacji. Wybranie Hermes jako domyślnego agenta instaluje to samo, co wpis _Instaluj > AI_: pakiet oraz runtime Hermes w `~/.hermes` skonfigurowany przez własny instalator Hermes, co za pierwszym razem zajmuje kilka minut. Ten runtime jest tym jednym Hermes, którego używa terminalowe polecenie `hermes`, domyślny agent i aplikacja, i aktualizuje się sam przez `hermes update`, a nie czeka na wydanie Omarchy. Instalacja przekazuje też Hermes motyw Omarchy jako skórkę o nazwie `omarchy`, za którą podąża każda powierzchnia Hermes przy przełączaniu motywów; wybierz inną w ustawieniach wyglądu Hermes albo przez `/skin`, jeśli nie chcesz, żeby tak było, a Omarchy zostawi ten wybór w spokoju. Usunięcie aplikacji pod _Usuń > AI_ najpierw zamyka Hermes, wraz z bramą, zabiera z nim ten runtime i zachowuje twoje czaty, pamięci oraz umiejętności, które Hermes napisał dla siebie, chyba że powiesz inaczej: pyta — z domyślną odpowiedzią nie — czy te dane i twoje ustawienia połączeń mają też zniknąć.

Doświadczeniem pulpitowym OpenClaw jest jego Control UI, które otwiera się jako aplikacja webowa wsparta jego własną lokalną bramą. OpenClaw mieszka w `~/.openclaw` i aktualizuje się sam: użyj przycisku "Update Gateway" w Control UI albo uruchom `openclaw update`, a brama wystartuje ponownie na nowej wersji. Omarchy wybiera jedynie wydanie, od którego zaczyna świeża instalacja. Usunięcie OpenClaw pod _Usuń > AI_ zabiera ze sobą usługę bramy i aplikację, a potem pyta, czy `~/.openclaw` też powinien zniknąć, bo zawiera twoje czaty i poświadczenia obok samego OpenClaw oraz pobieranych przez niego runtime'ów wtyczek; domyślnie zostaje, a ponowna instalacja OpenClaw go przechwytuje z powrotem.

### Lokalne LLM-y

Omarchy poleca dwa sposoby uruchamiania lokalnych modeli LLM: LM Studio oraz Ollama. LM Studio zapewnia interfejs graficzny do wyszukiwania modeli open-weight, instalowania ich oraz uruchamiania. To świetny sposób na łatwy start. Ollama oferuje do tego CLI w podobny sposób. Ale jeśli jesteś nowy w modelach lokalnych, zacząłbym od LM Studio. Każdy z nich możesz zainstalować pod _Instaluj > AI_ w menu Omarchy.

### Omarchy Skill

Umiejętności agentów pomagają AI używać określonych narzędzi w określony sposób, a Omarchy jest dostarczany z domyślną umiejętnością dostosowywania systemu. Na przykład drobne poprawki konfiguracji Hyprland, dostrajanie paska albo nawet tworzenie nowego motywu od zera. Jest podłączona symbolicznie do katalogów umiejętności dla Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i każdego `~/.hermes/profiles/*/skills`) oraz ogólnej lokalizacji `~/.agents/skills`, więc większość osprzętów przechwytuje ją automatycznie.

Powinieneś jednak traktować tę umiejętność jako eksperymentalną. Różne modele użyją jej z różnym skutkiem. Najlepiej najpierw działać w trybie planowania, żeby mieć pojęcie, co agent chciałby zmienić. A potem być gotowym na wycofanie zmian albo nawet wywołanie `omarchy reinstall configs`, jeśli agent narobi bałaganu.
