# KI

Omarchy behandelt KI-Coding-Agenten als Bürger erster Klasse, wählt aber keinen Favoriten für dich. Stattdessen ist jede große Coding-Agent-CLI als lazy-geladener Launcher vorverdrahtet. Die Launcher sind winzige, von [mise](https://mise.jdx.dev/) verwaltete Stubs in `~/.local/bin/`, sodass nichts heruntergeladen wird, bis du einen tatsächlich zum ersten Mal ausführst. Hermes ist die Ausnahme: Für ihn ist nichts gestubbt, und seine Auswahl installiert Hermes Desktop, wie _Desktop-Apps_ unten erklärt. Rufe einen davon auf und authentifiziere dich, wenn du dazu aufgefordert wirst:

| Befehl    | Agent                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) von xAI                        |
| `pi`       | [Mario Zechners Pi](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), OpenRouters Harness |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), Nous Researchs Agent  |
| `muse`     | [Muse Code](https://dev.meta.ai), Metas Coding-Agent           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` ist der Außenseiter: Er führt die anderen Harnesses gegen OpenRouters gesamten Modellkatalog aus, sodass `ori claude`, `ori codex` oder `ori opencode` diese Agenten auf dem Modell starten, auf das du sie zeigst, und `ori code` ist Oris eigener Agent.

Um eine zusätzliche CLI auf dieselbe Weise zu verpacken, führe `omarchy-mise-install <package> [command-name]` aus. Die Stubs werden zusammen mit allem anderen, was mise verwaltet, aktuell gehalten, wenn du `omarchy update` (oder den Alias `mup`) ausführst.

`grok` wird über mises First-Party-Paket `grok` installiert, auf dieselbe Weise wie `claude` und `codex`. Führe `grok` aus oder wähle es unter _Einrichtung > Standards > Agent_. Überspringe den `curl | bash`-Installer auf x.ai. Dieser Weg legt eine zweite Kopie in `~/.grok/bin` ab, stellt sie im `PATH` voran und überschreibt Omarchys Wrapper.

### Der Standard-Agent

Wähle deinen Standard-Agenten mit `omarchy default agent <name>` oder unter _Einrichtung > Standards > Agent_ im Omarchy-Menü (`Super + Space`). Wenn der Agent noch nicht installiert ist, installiert ihn die Auswahl zuerst. Ein frisches Omarchy lädt dich mit einer einmaligen Benachrichtigung ein, diese Wahl zu treffen.

Die Auswahl von Claude versucht auch, seine Browser-Erweiterung für Chromium, Chrome, Brave, Brave Origin und Edge einzurichten. Die Einrichtung der Erweiterung gilt für alle Benutzer und fragt möglicherweise nach deinem Systempasswort; ein Abbruch oder eine fehlgeschlagene Installation der Erweiterung wählt und startet Claude trotzdem. Starte deinen Browser neu, aktiviere die Erweiterung, wenn du dazu aufgefordert wirst, und melde dich bei Claude an, um die Verbindung abzuschließen. Führe `/chrome` in Claude aus, um die Verbindung zu prüfen. Firefox und Zen unterstützen diese Erweiterung nicht. Wenn Claude bereits dein Standard war, bevor diese Einrichtung hinzugefügt wurde, wähle ihn erneut, um die Erweiterung zu installieren.

[Muse Code](https://dev.meta.ai) — Metas `muse` — verwendet einen vorinstallierten mise-Stub wie die anderen Agenten. Seine Auswahl als Standard installiert Metas offiziellen Launcher über mises HTTP-Backend. Der Launcher verifiziert und aktualisiert das native Binary für deine Maschine.

Sobald du gewählt hast, startet `Super + Shift + Ctrl + A` den Standard-Agenten in einem dedizierten Terminalfenster (oder ruft die Auswahl auf, wenn du noch nicht gewählt hast). Du kannst ihn auch direkt in eine Aufgabe starten mit `omarchy agent prompt "Review this project"`. Auf diese Weise gestartete Agenten laufen unbeaufsichtigt in ihren jeweiligen Nicht-Anhalten-zum-Fragen-Modi, also sei bereit, dass sie tatsächlich Dinge tun! Und da Agenten sich weigern, sich Vertrauen für dein Home-Verzeichnis zu merken, starten Starts aus `$HOME` stattdessen in `~/Work`.

Es gibt auch Terminal-Tastenkürzel: `a` führt den Standard-Agenten inline im aktuellen Terminal aus, während `c`, `cx` und `cy` OpenCode, Claude Code und Codex direkt starten (wiederum in ihren automatisch genehmigenden Modi). Design-Änderungen synchronisieren sich auch zu den Agenten: Claude Code, Pi, OpenCode und Hermes (sobald Omarchy ihn installiert hat) folgen alle mit, wenn du das Omarchy-Design wechselst.

### Das Agenten-Panel

Die Menüleiste hat ein Agenten-Symbol. Bevor du einen Agenten eingerichtet hast, führt dich sein Panel durch die Anmeldung bei Claude, Codex oder Grok, und der erste wird dein Standard-Agent. Danach legt das Panel jedes Abonnement auf eine Seite: jeden Agenten und jedes Konto mit seinem Plan, eine Anzeige für jedes seiner 5-Stunden-Sitzungs- und Wochenlimits mit der Zeit bis zum Zurücksetzen (darüberfahren für den exakten Prozentsatz) oder das verbleibende Prepaid-Guthaben, unter einer Zeile, die durchwechselt, was du über sie alle hinweg verwendet hast, wie Tokens diese Woche und dein meistgenutztes Modell. Unter _Make something_ bietet es Starter-Prompts für ein neues Design, Plugin oder eine App, die die Aufgabe an deinen Standard-Agenten übergeben. Apps werden so gebaut, wie Omarchys eigene Hype, Monologue und Omacut gebaut sind, in C++ und Qt Quick, dem omarchy-app-Agent-Skill folgend, und der Compiler und die Qt-Teile, die sie brauchen, sind mitinstalliert. Claude Code, Codex, Grok und Fireworks werden sofort einsatzbereit abgedeckt.

Linksklicke auf das Leistensymbol für das Panel, rechtsklicke, um deinen Standard-Agenten zu starten. Die dahinterstehenden Nutzungsdatensätze werden alle 15 Minuten von `omarchy agent usage-update` neu generiert, und das Panel kann Nutzung sogar von deinen anderen Maschinen über einen synchronisierten Ordner zusammenführen. Siehe die README unter `$OMARCHY_PATH/shell/plugins/agents/` für die vollständigen Einstellungen.

### Mehrere Abonnements

Wenn du für mehr als einen Claude-, Codex- oder Grok-Plan zahlst — zum Beispiel ein persönliches Max und eines für die Arbeit — kann Omarchy sie alle angemeldet halten und zwischen ihnen wechseln. Füge ein Abonnement mit dem + im Agenten-Panel hinzu, das dich direkt dort hindurchführt, oder mit `omarchy agent account add claude Work` (oder `codex` oder `grok`). Es installiert die CLI, wenn sie fehlt. Das erste Konto für einen Anbieter meldet sich über deinen normalen Browser an, genau dort, wo die CLI immer sucht. Jedes danach meldet sich über ein privates Fenster an, sodass das Konto, bei dem dein Browser bereits angemeldet ist, nicht versehentlich ausgewählt wird; melde dich dort als das Konto an, das du hinzufügst, und schließe vorher jedes private Fenster, das du bereits offen hattest. Melde dich dafür niemals von der CLI ab: Abmelden widerruft die gespeicherte Anmeldung, und dieses Konto müsste erneut hinzugefügt werden.

Ein Konto pro Anbieter ist aktiv, und jede neue Sitzung startet als dieses: `cx`, `cy`, ein einfaches `claude`, `codex` oder `grok`, alles, was über `omarchy agent` gestartet wird, und Skripte oder Editoren, die die CLI im `PATH` finden. Wechsle mit `omarchy agent account use work` (und zurück mit `omarchy agent account use main`) oder im Panel, indem du die Nummer eines Kontos drückst und dann `Enter` (oder auf seine Use-Schaltfläche klickst). Sitzungen, die bereits laufen, bleiben auf dem Konto, mit dem sie gestartet sind. Gesprächsverlauf, Einstellungen, Skills und Plugins werden über Konten hinweg geteilt, sodass `claude --continue` im selben Ordner dort weitermacht, wo du auf dem neuen Konto aufgehört hast.

Mit mehr als einem Konto zeigt das Panel die Limits jedes Kontos nebeneinander, mit dem aktiven markiert. Standardmäßig benachrichtigt dich Omarchy, wenn das aktive Konto 95 % eines Limits überschreitet, und ein Klick auf die Benachrichtigung wechselt zu dem Konto mit dem meisten Spielraum. Fahre mit der Maus über die Zeile eines Kontos im Panel und klicke auf den Autoswitch, der neben Use erscheint (oder drücke `m`), oder führe `omarchy agent account mode auto` aus, damit es stattdessen von selbst wechselt; während es eingeschaltet ist, nimmt Autoswitch den Platz von Use ein, und ein erneuter Klick geht zurück zum Benachrichtigen. Füge eine Zahl hinzu, um den Schwellenwert zu ändern, wie in `omarchy agent account mode auto 90`. Wenn jedes Konto über dem Schwellenwert ist, hörst du einmal davon, zusammen damit, welches Konto zuerst frei wird. Während ein aktives Konto innerhalb von 15 Punkten seines Schwellenwerts ist (80 % beim Standard), werden seine Limits alle drei Minuten statt alle 15 geprüft.

`omarchy agent account list` zeigt jedes Konto und seine neuesten Limits, `omarchy agent account remove work` vergisst eines, und `omarchy agent account rename primary Hey` benennt eines um (oder klicke auf den Namen eines Kontos im Panel). Diese Befehle arbeiten auf den Konten deines Standard-Agenten; um den anderen Anbieter zu erreichen, nenne ihn zuerst, wie in `omarchy agent account use codex side`. Die Anmeldung, die du bereits in `~/.claude` oder `~/.codex` hattest, ist das _Main_-Konto und bleibt, wo sie ist. Ein Konto, das mehr als etwa acht Stunden ungenutzt bleibt, kann _Sign-in required_ zeigen; klicke darauf, um dieses Konto direkt im Panel erneut anzumelden, oder starte eine Sitzung darin, was die Anmeldung von selbst auffrischt. MCP-Server, die du hattest, als ein Konto hinzugefügt wurde, kommen mit zu ihm, aber solche, die du später mit `claude mcp add` hinzufügst, erreichen nur das Konto, in dem du sie hinzugefügt hast. Claude Desktop und Werkzeuge, die mit einem absoluten Pfad zu einem CLI-Binary konfiguriert sind, folgen dem Wechsel nicht. Ein explizites `CLAUDE_CONFIG_DIR`, `CODEX_HOME` oder `GROK_HOME` hat Vorrang vor dem ausgewählten Konto.

### Absturzdiagnose

Omarchy überwacht systemd-coredump auf Prozessabstürze. Wenn etwas segfaultet, bekommst du eine Benachrichtigung „Process crashed“ — klicke darauf, und der Absturz wird an deinen Standard-Agenten übergeben, zusammen mit Omarchys Diagnose-crash-Skill, der den Agenten dadurch führt, die Fakten aus dem Core-Dump festzustellen und zu entscheiden, ob es sich lohnt, den Absturz upstream zu melden. Du kannst ihn auch von Hand gegen jede PID aus `coredumpctl list` mit `omarchy agent crash <pid>` ausführen.

Die Überwachung ist standardmäßig eingeschaltet. Schalte sie unter _Auslösen > Umschalten > Absturzerfassung_ aus (oder mit `omarchy toggle crash-capture`), und die Benachrichtigungen hören auf; `omarchy agent crash <pid>` funktioniert weiterhin von Hand.

Abstürze können auch ein Programm nach dem anderen stummgeschaltet werden, was dir die Diagnose am Ende anbietet. `omarchy crash mute hyprland` stoppt die Benachrichtigungen nur für dieses Programm, `omarchy crash mute hyprland off` bringt sie zurück, und `omarchy crash mute` allein listet auf, was du stummgeschaltet hast. Es nimmt den Pfad des Binarys genauso gern wie seinen Namen, sodass `omarchy crash mute /usr/bin/hyprland` dasselbe tut. Setze einen Namen mit einem Leerzeichen in Anführungszeichen, wie in `omarchy crash mute 'Some App'`. Alles andere benachrichtigt weiterhin, und das stummgeschaltete Programm stürzt weiterhin ab — das versteckt die Erinnerung, es behebt nichts.

### Desktop-Apps

Das Menü _Installieren > KI_ trägt auch ein paar grafische KI-Apps: die ChatGPT-Desktop-App, die Claude-Desktop-App (Anthropics Linux-Beta, mit Tabs für Chat, Cowork und Claude Code), Grok Bot zum Chatten mit xAIs Modellen, Hermes Desktop, OpenClaw und die Perplexity-Desktop-App. Grok Bot ist die Desktop-Chat-App. Der Coding-Agent ist der Befehl `grok`.

Hermes Desktop ist die, von der man wissen sollte, weil eine Maschine ein Hermes hat, und es ist das der App: Hermes wird nur jemals über die App installiert, und der Befehl `hermes`, den der Standard-Agent ausführt, ist der der App. Die Auswahl von Hermes als Standard-Agent installiert dasselbe wie der Eintrag _Installieren > KI_: das Paket und eine Hermes-Runtime unter `~/.hermes`, eingerichtet von Hermes' eigenem Installer, was beim ersten Mal ein paar Minuten dauert. Diese Runtime ist die eine Hermes-Runtime, die das Terminal mit dem Befehl `hermes`, der Standard-Agent und die App alle verwenden, und sie aktualisiert sich selbst mit `hermes update`, statt auf eine Omarchy-Version zu warten. Ihre Installation übergibt Hermes auch das Omarchy-Design als Skin namens `omarchy`, dem jede Hermes-Oberfläche folgt, wenn du Designs wechselst; wähle einen anderen unter Hermes' Appearance-Einstellungen oder mit `/skin`, wenn du das lieber nicht willst, und Omarchy lässt diese Wahl in Ruhe. Das Entfernen der App unter _Entfernen > KI_ schließt Hermes zuerst, Gateway eingeschlossen, nimmt diese Runtime mit und behält deine Chats, Erinnerungen und die Skills, die Hermes für sich selbst geschrieben hat, es sei denn, du sagst ihm etwas anderes: Es fragt, mit Standard Nein, ob diese Daten und deine Verbindungseinstellungen auch weg sollen.

OpenClaws Desktop-Erlebnis ist seine Control UI, die als Web-App öffnet, gestützt von seinem eigenen lokalen Gateway. OpenClaw lebt in `~/.openclaw` und aktualisiert sich selbst: Verwende die Schaltfläche „Update Gateway“ der Control UI oder führe `openclaw update` aus, und das Gateway startet auf der neuen Version neu. Omarchy wählt nur die Version, von der eine frische Installation startet. Das Entfernen von OpenClaw unter _Entfernen > KI_ nimmt den Gateway-Dienst und die App mit und fragt dann, ob `~/.openclaw` auch weg soll, da das deine Chats und Zugangsdaten neben OpenClaw selbst und den Plugin-Runtimes enthält, die es herunterlädt; der Standard behält es, und die erneute Installation von OpenClaw nimmt es wieder auf.

### Lokale LLMs

Omarchy empfiehlt zwei Wege, lokale LLM-Modelle auszuführen: LM Studio und Ollama. LM Studio bietet eine GUI-Oberfläche, um Open-Weight-Modelle zu finden, zu installieren und auszuführen. Es ist ein großartiger Weg, einfach loszulegen. Ollama bietet eine CLI, um dasselbe zu tun. Aber wenn du neu bei lokalen Modellen bist, würde ich mit LM Studio anfangen. Du kannst beides unter _Installieren > KI_ im Omarchy-Menü installieren.

### Der Omarchy-Skill

Agent-Skills helfen KI, bestimmte Werkzeuge auf eine bestimmte Weise zu verwenden, und Omarchy liefert einen Standard-Skill mit, um das System anzupassen. Wie deine Hyprland-Konfiguration zu optimieren, die Leiste anzupassen oder sogar ein neues Design von Grund auf zu erstellen. Er ist in die Skill-Verzeichnisse für Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` und jedes `~/.hermes/profiles/*/skills`) und den generischen Ort `~/.agents/skills` symlinkiert, sodass die meisten Harnesses ihn automatisch aufgreifen.

Aber du solltest diesen Skill als experimentell behandeln. Verschiedene Modelle werden ihn mit unterschiedlicher Wirkung verwenden. Es ist am besten, ihn zuerst im Plan-Modus auszuführen, sodass du eine Idee davon hast, was der Agent gerne ändern würde. Und sei dann bereit, Änderungen zurückzunehmen oder sogar `omarchy reinstall configs` aufzurufen, wenn der Agent aus allem ein Durcheinander macht.
