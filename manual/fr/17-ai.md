# IA

Omarchy traite les agents de codage IA comme des citoyens de première classe, mais il ne choisit pas un favori pour vous. À la place, chaque CLI majeure d'agent de codage est pré-câblée comme lanceur à chargement paresseux. Les lanceurs sont de minuscules stubs gérés par [mise](https://mise.jdx.dev/) dans `~/.local/bin/`, de sorte que rien n'est téléchargé avant la première fois où vous en exécutez réellement un. Hermes est l'exception : rien n'est stubbé pour lui, et le choisir installe Hermes Desktop, comme l'explique _Applis bureau_ ci-dessous. Invoquez l'un d'entre eux et authentifiez-vous lorsque vous y êtes invité :

| Commande    | Agent                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) de xAI                        |
| `pi`       | [Pi de Mario Zechner](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), le harnais d'OpenRouter |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), l'agent de Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai), l'agent de codage de Meta           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` est l'étranger : il fait tourner les autres harnais sur tout le catalogue de modèles d'OpenRouter, de sorte que `ori claude`, `ori codex` ou `ori opencode` démarrent ces agents sur le modèle que vous leur indiquez, et `ori code` est le propre agent d'Ori.

Pour envelopper une CLI supplémentaire de la même façon, exécutez `omarchy-mise-install <package> [command-name]`. Les stubs sont maintenus à jour avec tout ce que mise gère lorsque vous exécutez `omarchy update` (ou l'alias `mup`).

`grok` est installé via le paquet first-party `grok` de mise, de la même façon que `claude` et `codex`. Exécutez `grok`, ou choisissez-le sous _Configuration > Par défaut > Agent_. Évitez l'installateur `curl | bash` sur x.ai. Ce chemin place une deuxième copie dans `~/.grok/bin`, l'ajoute en tête du `PATH`, et écrase le wrapper d'Omarchy.

### L'agent par défaut

Choisissez votre agent par défaut avec `omarchy default agent <name>` ou sous _Configuration > Par défaut > Agent_ dans le menu Omarchy (`Super + Space`). Si l'agent n'est pas encore installé, le choisir l'installe d'abord. Un Omarchy frais vous invitera à faire ce choix avec une notification unique.

Choisir Claude tente aussi de configurer son extension navigateur pour Chromium, Chrome, Brave, Brave Origin et Edge. La configuration de l'extension s'applique à tous les utilisateurs et peut demander votre mot de passe système ; annuler ou échouer l'installation de l'extension sélectionne et lance quand même Claude. Redémarrez votre navigateur, activez l'extension si vous y êtes invité, et connectez-vous à Claude pour terminer la connexion. Exécutez `/chrome` dans Claude pour vérifier la connexion. Firefox et Zen ne prennent pas en charge cette extension. Si Claude était déjà votre agent par défaut avant l'ajout de cette configuration, sélectionnez-le à nouveau pour installer l'extension.

[Muse Code](https://dev.meta.ai) — le `muse` de Meta — utilise un stub mise préinstallé comme les autres agents. Le choisir comme agent par défaut installe le lanceur officiel de Meta via le backend HTTP de mise. Le lanceur vérifie et met à jour le binaire natif pour votre machine.

Une fois que vous avez choisi, `Super + Shift + Ctrl + A` lance l'agent par défaut dans une fenêtre de terminal dédiée (ou affiche le sélecteur si vous n'avez pas encore choisi). Vous pouvez aussi le lancer directement dans une tâche avec `omarchy agent prompt "Review this project"`. Les agents lancés ainsi tournent sans surveillance dans leurs modes respectifs ne-pas-s'arrêter-pour-demander, alors soyez prêt à les voir réellement faire des choses ! Et comme les agents refusent de se souvenir de la confiance pour votre répertoire personnel, les lancements depuis `$HOME` démarrent à la place dans `~/Work`.

Il y a aussi des raccourcis terminal : `a` exécute l'agent par défaut en ligne dans le terminal actuel, tandis que `c`, `cx` et `cy` démarrent directement OpenCode, Claude Code et Codex (encore une fois dans leurs modes d'approbation automatique). Les changements de thème se synchronisent aussi vers les agents : Claude Code, Pi, OpenCode et Hermes (une fois qu'Omarchy l'a installé) suivent tous lorsque vous changez le thème Omarchy.

### Le panneau agents

La barre supérieure a une icône agents. Avant que vous ayez configuré un agent, son panneau vous guide pour vous connecter à Claude, Codex ou Grok, et le premier devient votre agent par défaut. Après cela, le panneau met chaque abonnement sur une page : chaque agent et compte avec son plan, un compteur pour chacune de ses limites de session de 5 heures et hebdomadaires avec le temps avant sa réinitialisation (survolez pour le pourcentage exact), ou le solde prépayé restant, sous une ligne qui fait défiler ce que vous avez utilisé chez tous, comme les jetons cette semaine et votre modèle le plus utilisé. Sous _Make something_, il offre des prompts de départ pour un nouveau thème, plugin ou appli qui confient la tâche à votre agent par défaut. Les applis sont construites à la façon des propres Hype, Monologue et Omacut d'Omarchy, en C++ et Qt Quick, en suivant le skill d'agent omarchy-app, et le compilateur et les éléments Qt dont elles ont besoin sont installés. Claude Code, Codex, Grok et Fireworks sont couverts dès l'installation.

Cliquez avec le bouton gauche sur l'icône de la barre pour le panneau, avec le bouton droit pour lancer votre agent par défaut. Les enregistrements d'utilisation qui le sous-tendent sont régénérés toutes les 15 minutes par `omarchy agent usage-update`, et le panneau peut même fusionner l'utilisation de vos autres machines via un dossier synchronisé. Voir le README sous `$OMARCHY_PATH/shell/plugins/agents/` pour tous les réglages.

### Plusieurs abonnements

Si vous payez plus d'un plan Claude, Codex ou Grok — un Max personnel et un professionnel, par exemple — Omarchy peut les garder tous connectés et passer de l'un à l'autre. Ajoutez un abonnement avec le + dans le panneau agents, qui vous guide là-même, ou avec `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Il installe la CLI si elle est manquante. Le premier compte pour un fournisseur se connecte via votre navigateur normal, exactement là où la CLI regarde toujours. Chaque suivant se connecte via une fenêtre privée, de sorte que le compte auquel votre navigateur est déjà connecté ne soit pas récupéré par erreur ; connectez-vous là comme le compte que vous ajoutez, et fermez d'abord toute fenêtre privée déjà ouverte. Ne vous déconnectez jamais de la CLI pour faire cela : se déconnecter révoque la connexion enregistrée, et ce compte devrait être ajouté à nouveau.

Un compte par fournisseur est actif, et chaque nouvelle session démarre comme lui : `cx`, `cy`, un simple `claude`, `codex` ou `grok`, tout ce qui est lancé via `omarchy agent`, et les scripts ou éditeurs qui trouvent la CLI sur le `PATH`. Basculez avec `omarchy agent account use work` (et revenez avec `omarchy agent account use main`), ou dans le panneau en appuyant sur le numéro d'un compte puis `Enter` (ou en cliquant son bouton Use). Les sessions déjà en cours restent sur le compte avec lequel elles ont commencé. L'historique de conversation, les réglages, les skills et les plugins sont partagés entre comptes, de sorte que `claude --continue` dans le même dossier reprend là où vous vous étiez arrêté sur le nouveau compte.

Avec plus d'un compte, le panneau affiche les limites de chaque compte côte à côte, avec l'actif marqué. Par défaut, Omarchy vous notifie lorsque le compte actif dépasse 95 % d'une limite, et cliquer sur la notification bascule vers le compte ayant le plus de marge. Survolez la ligne d'un compte dans le panneau et cliquez sur l'Autoswitch qui apparaît à côté de Use (ou appuyez sur `m`), ou exécutez `omarchy agent account mode auto`, pour qu'elle bascule toute seule ; pendant qu'elle est active, Autoswitch prend la place de Use, et recliquer dessus revient à notifier. Ajoutez un nombre pour changer le seuil, comme dans `omarchy agent account mode auto 90`. Si chaque compte dépasse le seuil, vous en serez informé une fois, avec le compte qui se libère en premier. Tant qu'un compte actif est à moins de 15 points de son seuil (80 % par défaut), ses limites sont vérifiées toutes les trois minutes plutôt que toutes les 15.

`omarchy agent account list` affiche chaque compte et ses dernières limites, `omarchy agent account remove work` en oublie un, et `omarchy agent account rename primary Hey` en renomme un (ou cliquez sur le nom d'un compte dans le panneau). Ces commandes fonctionnent sur les comptes de votre agent par défaut ; pour atteindre l'autre fournisseur, nommez-le d'abord, comme dans `omarchy agent account use codex side`. La connexion que vous aviez déjà dans `~/.claude` ou `~/.codex` est le compte _Main_ et reste où elle est. Un compte laissé inutilisé pendant plus d'environ huit heures peut afficher _Sign-in required_ ; cliquez dessus pour reconnecter ce compte directement dans le panneau, ou démarrez une session dedans, ce qui actualise la connexion tout seul. Les serveurs MCP que vous aviez lorsqu'un compte a été ajouté le suivent, mais ceux que vous ajoutez plus tard avec `claude mcp add` n'atteignent que le compte dans lequel vous les avez ajoutés. Claude Desktop et les outils configurés avec un chemin absolu vers un binaire CLI ne suivent pas la bascule. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explicite prend le pas sur le compte sélectionné.

### Diagnostic de crash

Omarchy surveille systemd-coredump pour les crashes de processus. Quand quelque chose fait un segfault, vous recevrez une notification « Process crashed » — cliquez dessus, et le crash est transmis à votre agent par défaut accompagné du skill diagnose-crash d'Omarchy, qui guide l'agent pour établir les faits à partir du core dump et décider si le crash vaut la peine d'être signalé en amont. Vous pouvez aussi l'exécuter à la main contre n'importe quel PID de `coredumpctl list` avec `omarchy agent crash <pid>`.

La surveillance est activée par défaut. Désactivez-la sous _Déclencher > Basculer > Capture de crash_ (ou avec `omarchy toggle crash-capture`) et les notifications s'arrêtent ; `omarchy agent crash <pid>` fonctionne toujours à la main.

Les crashes peuvent aussi être silenciés un programme à la fois, ce que le diagnostic vous propose à la fin. `omarchy crash mute hyprland` arrête les notifications pour ce programme seulement, `omarchy crash mute hyprland off` les ramène, et `omarchy crash mute` tout seul liste ce que vous avez silencié. Il accepte le chemin du binaire aussi volontiers que son nom, de sorte que `omarchy crash mute /usr/bin/hyprland` fait la même chose. Mettez entre guillemets un nom avec un espace, comme dans `omarchy crash mute 'Some App'`. Tout le reste continue de notifier, et le programme silencié continue de crasher — ceci masque le rappel, cela ne répare rien.

### Applis bureau

Le menu _Installer > AI_ contient aussi quelques applis IA graphiques : l'appli bureau ChatGPT, l'appli bureau Claude (la bêta Linux d'Anthropic, avec les onglets Chat, Cowork et Claude Code), Grok Bot pour discuter avec les modèles de xAI, Hermes Desktop, OpenClaw et l'appli bureau Perplexity. Grok Bot est l'appli de chat bureau. L'agent de codage est la commande `grok`.

Hermes Desktop est celui à connaître, parce qu'une machine a un seul Hermes, et c'est celui de l'appli : Hermes n'est jamais installé que via l'appli, et la commande `hermes` que l'agent par défaut exécute est celle de l'appli. Choisir Hermes comme agent par défaut installe la même chose que l'entrée _Installer > AI_ : le paquet, et un runtime Hermes sous `~/.hermes` configuré par le propre installateur de Hermes, ce qui prend quelques minutes la première fois. Ce runtime est le seul Hermes que la commande terminal `hermes`, l'agent par défaut et l'appli utilisent tous, et il se met à jour lui-même avec `hermes update` plutôt que d'attendre une version d'Omarchy. L'installer donne aussi à Hermes le thème Omarchy comme skin nommé `omarchy`, que chaque surface Hermes suit lorsque vous changez de thème ; choisissez-en un autre sous les réglages Apparence de Hermes ou avec `/skin` si vous préférez qu'il ne le fasse pas, et Omarchy laisse ce choix tranquille. Supprimer l'appli sous _Supprimer > AI_ ferme d'abord Hermes, gateway incluse, emporte ce runtime avec lui, et conserve vos chats, mémoires et les skills que Hermes a écrits pour lui-même à moins que vous ne lui disiez le contraire : il demande, avec non par défaut, si ces données et vos réglages de connexion doivent aussi partir.

L'expérience bureau d'OpenClaw est son interface Control UI, qui s'ouvre comme une web app adossée à sa propre gateway locale. OpenClaw vit dans `~/.openclaw` et se met à jour lui-même : utilisez le bouton « Update Gateway » de la Control UI ou exécutez `openclaw update`, et la gateway redémarre sur la nouvelle version. Omarchy choisit seulement la version à partir de laquelle une nouvelle installation démarre. Supprimer OpenClaw sous _Supprimer > AI_ emporte le service gateway et l'appli avec lui, puis demande si `~/.openclaw` doit aussi partir, puisque cela contient vos chats et identifiants aux côtés d'OpenClaw lui-même et des runtimes de plugins qu'il télécharge ; la valeur par défaut le conserve, et réinstaller OpenClaw le récupère.

### LLM locaux

Omarchy recommande deux façons d'exécuter des modèles LLM locaux : LM Studio et Ollama. LM Studio fournit une interface graphique pour trouver des modèles à poids ouverts, les installer et les exécuter. C'est un excellent moyen de démarrer facilement. Ollama offre une CLI pour faire de même. Mais si vous débutez avec les modèles locaux, je commencerais par LM Studio. Vous pouvez installer l'un ou l'autre sous _Installer > AI_ dans le menu Omarchy.

### Le skill Omarchy

Les skills d'agent aident l'IA à utiliser des outils spécifiques d'une façon spécifique, et Omarchy est livré avec un skill par défaut pour adapter le système. Comme ajuster votre configuration Hyprland, régler la barre, ou même créer un nouveau thème à partir de zéro. Il est lié par lien symbolique dans les répertoires de skills pour Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` et chaque `~/.hermes/profiles/*/skills`), et l'emplacement générique `~/.agents/skills`, de sorte que la plupart des harnais le récupèrent automatiquement.

Mais vous devriez traiter ce skill comme expérimental. Différents modèles l'utiliseront avec des effets différents. Il vaut mieux d'abord tourner en mode plan, pour avoir une idée de ce que l'agent voudrait changer. Et ensuite être prêt à annuler les changements ou même à invoquer `omarchy reinstall configs`, si l'agent met le chaos partout.
