# AI

يعامل Omarchy وكلاء ترميز AI كمواطنين من الدرجة الأولى، لكنه لا يختار لك مفضّلًا. بدلًا من ذلك، كل CLI رئيسي لوكيل ترميز يأتي موصولًا مسبقًا كمشغّل محمّل كسولًا. المشغّلات هي بذرات صغيرة مدارة بـ [mise](https://mise.jdx.dev/) في `~/.local/bin/`، لذا لا يُنزّل شيء حتى أول مرة تُشغّل فيها واحدة فعلًا. Hermes هو الاستثناء: لا شيء مبذّر له، واختياره يثبّت Hermes Desktop، كما يشرح _تطبيقات سطح المكتب_ أدناه. استدعِ أيًا من هذه وصادق عندما يُطلب:

| الأمر    | الوكيل                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) من xAI                        |
| `pi`       | [Mario Zechner's Pi](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness)، حزام OpenRouter |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/)، وكيل Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai)، وكيل ترميز Meta           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` هو الغريب: يُشغّل الأحزمة الأخرى مقابل كتالوج نماذج OpenRouter بأكمله، لذا `ori claude` أو `ori codex` أو `ori opencode` تبدأ تلك الوكلاء على أي نموذج تشير إليه، و`ori code` هو وكيل Ori الخاص.

لالتفاف CLI إضافي بنفس الطريقة، شغّل `omarchy-mise-install <package> [command-name]`. تُبقى البذرات محدّثة جنبًا إلى جنب مع كل شيء آخر يديره mise عندما تُشغّل `omarchy update` (أو اسم `mup` المستعار).

`grok` يُثبَّت عبر حزمة mise الطرف الأول `grok`، بنفس طريقة `claude` و`codex`. شغّل `grok`، أو اختره تحت _الإعداد > الافتراضية > الوكيل_. تخطّى مثبّت `curl | bash` على x.ai. ذلك المسار يضع نسخة ثانية في `~/.grok/bin`، ويقدّمها على `PATH`، ويكتب فوق غلاف Omarchy.

### الوكيل الافتراضي

اختر وكيلك الافتراضي بـ `omarchy default agent <name>` أو تحت _الإعداد > الافتراضية > الوكيل_ في قائمة Omarchy (`Super + Space`). إذا لم يكن الوكيل مثبّتًا بعد، فإن اختياره يثبّته أولًا. Omarchy جديد سيدعوك لاتخاذ هذا الاختيار بإشعار لمرة واحدة.

اختيار Claude يحاول أيضًا إعداد امتداد المتصفّح لـ Chromium وChrome وBrave وBrave Origin وEdge. ينطبق إعداد الامتداد على كل المستخدمين وقد يسأل عن كلمة مرور نظامك؛ الإلغاء أو تثبيت امتداد فاشل يبقى يحدّد ويُطلق Claude. أعد تشغيل متصفّحك، وفعّل الامتداد إذا طُلب، وسجّل الدخول إلى Claude لإنهاء ربطه. شغّل `/chrome` في Claude للتحقّق من الاتصال. Firefox وZen لا يدعمان هذا الامتداد. إذا كان Claude وكيلك الافتراضي بالفعل قبل إضافة هذا الإعداد، حدّده مرة أخرى لتثبيت الامتداد.

[Muse Code](https://dev.meta.ai) — `muse` من Meta — يستخدم بذرة mise مثبّتة مسبقًا مثل الوكلاء الآخرين. اختياره كافتراضي يثبّت مشغّل Meta الرسمي عبر خلفية mise HTTP. يتحقّق المشغّل ويحدّث الثنائي الأصلي لجهازك.

بمجرد اختيارك، يطلق `Super + Shift + Ctrl + A` الوكيل الافتراضي في نافذة طرفية مخصصة (أو يُظهر المنتقي إذا لم تختر بعد). يمكنك أيضًا إطلاقه مباشرة إلى مهمة بـ `omarchy agent prompt "Review this project"`. الوكلاء المطلقون بهذه الطريقة يعملون دون مراقبة في أوضاع لا تتوقّف للسؤال الخاصة بهم، لذا كن مستعدًا لهم لفعل أشياء فعلًا! ولأن الوكلاء يرفضون تذكّر الثقة لدليلك الرئيسي، فإن الإطلاقات من `$HOME` تبدأ في `~/Work` بدلًا من ذلك.

هناك اختصارات طرفية أيضًا: `a` يُشغّل الوكيل الافتراضي مضمّنًا في الطرفية الحالية، بينما `c` و`cx` و`cy` تبدأ OpenCode وClaude Code وCodex مباشرة (مرة أخرى في أوضاع الموافقة التلقائية). تتزامن تغييرات السمات إلى الوكلاء أيضًا: Claude Code وPi وOpenCode وHermes (بمجرد أن يثبّته Omarchy) كلها تتبع عندما تبدّل سمة Omarchy.

### لوحة الوكلاء

للشريط العلوي أيقونة وكلاء. قبل إعدادك وكيلًا، ترشدك لوحته عبر تسجيل الدخول إلى Claude أو Codex أو Grok، ويصبح الأول وكيلك الافتراضي. بعد ذلك، تضع اللوحة كل اشتراك على صفحة واحدة: كل وكيل وحساب مع خطّته، وعدّاد لكل من حدود جلسته 5 ساعات وحدوده الأسبوعية مع الوقت حتى إعادة تعيينه (مرّر للنسبة الدقيقة)، أو الرصيد المدفوع المسبق المتبقي، تحت سطر يدوّر عبر ما استخدمته عبر كلها، مثل الرموز هذا الأسبوع ونموذجك الأكثر استخدامًا. تحت _صنع شيئًا_ يقدّم موجّهات بداية لسمة جديدة أو مكون إضافي أو تطبيق تسلّم المهمة إلى وكيلك الافتراضي. تُبنى التطبيقات بالطريقة التي تُبنى بها تطبيقات Omarchy الخاصة Hype وMonologue وOmacut، بـ C++ وQt Quick، باتباع مهارة وكيل omarchy-app، وقطع المترجم وQt التي تحتاجها تأتي مثبّتة. Claude Code وCodex وGrok وFireworks مغطّاة خارج الصندوق.

انقر بالزر الأيسر على أيقونة الشريط للوحة، وانقر بالزر الأيمن لإطلاق وكيلك الافتراضي. سجلات الاستخدام خلفها تُجدَّد كل 15 دقيقة بواسطة `omarchy agent usage-update`، ويمكن للوحة حتى دمج استخدام من أجهزتك الأخرى عبر مجلد متزامن. راجع README تحت `$OMARCHY_PATH/shell/plugins/agents/` للإعدادات الكاملة.

### اشتراكات متعددة

إذا دفعت مقابل أكثر من خطّة Claude أو Codex أو Grok واحدة — Max شخصي وواحد للعمل، قل — يمكن لـ Omarchy إبقاء كلها مسجّلًا الدخول والتنقّل بينها. أضف اشتراكًا بـ + في لوحة الوكلاء، الذي يرشدك عبره هناك بالضبط، أو بـ `omarchy agent account add claude Work` (أو `codex`، أو `grok`). يثبّت CLI إذا كان مفقودًا. الحساب الأول لمزوّد يسجّل الدخول عبر متصفّحك الطبيعي، بالضبط حيث يبحث CLI دائمًا. كل واحد بعد ذلك يسجّل الدخول عبر نافذة خاصة، بحيث لا يُلتقط الحساب الذي متصفّحك مسجّل فيه بالفعل عن طريق الخطأ؛ سجّل الدخول هناك كالحساب الذي تضيفه، وأغلق أي نافذة خاصة كانت مفتوحة لديك بالفعل أولًا. لا تسجّل أبدًا الخروج من CLI لفعل ذلك: تسجيل الخروج يلغي تسجيل الدخول المحفوظ، وسيتعيّن إضافة ذلك الحساب مرة أخرى.

حساب واحد لكل مزوّد نشط، وكل جلسة جديدة تبدأ به: `cx` و`cy` و`claude` عادي أو `codex` أو `grok`، وأي شيء مُطلق عبر `omarchy agent`، والبرامج النصية أو المحرّرات التي تجد CLI على `PATH`. بدّل بـ `omarchy agent account use work` (وعُد بـ `omarchy agent account use main`)، أو في اللوحة بالضغط على رقم حساب ثم `Enter` (أو النقر على زر استخدامه). الجلسات العاملة بالفعل تبقى على الحساب الذي بدأت به. سجل المحادثات والإعدادات والمهارات والمكونات الإضافية مشتركة عبر الحسابات، لذا `claude --continue` في نفس المجلد يلتقط من حيث تركت على الحساب الجديد.

مع أكثر من حساب واحد، تعرض اللوحة حدود كل حساب جنبًا إلى جنب، مع النشط معلّمًا. افتراضيًا يشعرك Omarchy عندما يمرّ الحساب النشط 95% من حد، والنقر على الإشعار يبدّل إلى الحساب مع أكبر هامش. مرّر على سطر حساب في اللوحة وانقر التبديل التلقائي الذي يظهر بجانب استخدامه (أو اضغط `m`)، أو شغّل `omarchy agent account mode auto`، لجعله يتبدّل بنفسه بدلًا من ذلك؛ بينما هو قيد التشغيل، يأخذ التبديل التلقائي مكان استخدامه، والنقر عليه مرة أخرى يعود إلى الإشعار. أضف رقمًا لتغيير العتبة، كما في `omarchy agent account mode auto 90`. إذا كان كل حساب فوق العتبة، ستسمع عن ذلك مرة واحدة، جنبًا إلى جنب مع أي حساب يتحرّر أولًا. بينما حساب نشط ضمن 15 نقطة من عتبته (80% في الافتراضي)، تُتحقّق حدوده كل ثلاث دقائق بدلًا من كل 15.

`omarchy agent account list` يعرض كل حساب وحدوده الأحدث، و`omarchy agent account remove work` ينسى واحدًا، و`omarchy agent account rename primary Hey` يعيد تسمية واحدًا (أو انقر اسم حساب في اللوحة). هذه الأوامر تعمل على حسابات وكيلك الافتراضي؛ للوصول إلى المزوّد الآخر، سمّه أولًا، كما في `omarchy agent account use codex side`. تسجيل الدخول الذي كان لديك بالفعل في `~/.claude` أو `~/.codex` هو الحساب _الرئيسي_ ويبقى أين هو. حساب تُرك غير مستخدم لأكثر من ثماني ساعات تقريبًا يمكن أن يُظهر _تسجيل الدخول مطلوب_؛ انقره لتسجيل ذلك الحساب مرة أخرى في اللوحة بالضبط، أو ابدأ جلسة فيه، التي تجدّد تسجيل الدخول بنفسها. خوادم MCP التي كانت لديك عندما أُضيف حساب تأتي معه إليه، لكن تلك التي تضيفها لاحقًا بـ `claude mcp add` تصل فقط إلى الحساب الذي أضفتها فيه. Claude Desktop وأدوات مكوّنة بمسار مطلق إلى ثنائي CLI لا تتبع التبديل. `CLAUDE_CONFIG_DIR` صريح أو `CODEX_HOME` أو `GROK_HOME` يأخذ أسبقية على الحساب المحدد.

### تشخيص الأعطال

يراقب Omarchy systemd-coredump لأعطال العمليات. عندما يحدث خطأ تقسيم لشيء ما، ستحصل على إشعار "Process crashed" — انقره، ويُسلَّم العطل إلى وكيلك الافتراضي جنبًا إلى جنب مع مهارة diagnose-crash في Omarchy، التي ترشد الوكيل عبر إثبات الحقائق من تفريغ النواة وتحديد ما إذا كان العطل يستحق الإبلاغ عنه في الأعلى. يمكنك أيضًا تشغيله يدويًا مقابل أي PID من `coredumpctl list` بـ `omarchy agent crash <pid>`.

المراقبة قيد التشغيل افتراضيًا. أوقفها تحت _تشغيل > تبديل > التقاط الأعطال_ (أو بـ `omarchy toggle crash-capture`) وتتوقّف الإشعارات؛ `omarchy agent crash <pid>` ما يزال يعمل يدويًا.

يمكن أيضًا إسكات الأعطال برنامجًا واحدًا في كل مرة، وهو ما يقدّمه التشخيص لك في النهاية. `omarchy crash mute hyprland` يوقف الإشعارات لذلك البرنامج فقط، و`omarchy crash mute hyprland off` يعيدها، و`omarchy crash mute` بمفرده يسرد ما أكتمته. يأخذ مسار الثنائي بسعادة كما اسمه، لذا `omarchy crash mute /usr/bin/hyprland` يفعل نفس الشيء. اقتبس اسمًا مع مسافة فيه، كما في `omarchy crash mute 'Some App'`. كل شيء آخر ما يزال يشعر، والبرنامج المكتم ما يزال يتعطّل — هذا يخفي التذكير، لا يصلح أي شيء.

### تطبيقات سطح المكتب

تحمل قائمة _تثبيت > AI_ أيضًا بعض تطبيقات AI الرسومية: تطبيق ChatGPT لسطح المكتب، وتطبيق Claude لسطح المكتب (بيتا Linux من Anthropic، مع علامات تبويب Chat وCowork وClaude Code)، وGrok Bot للدردشة مع نماذج xAI، وHermes Desktop، وOpenClaw، وتطبيق Perplexity لسطح المكتب. Grok Bot هو تطبيق دردشة سطح المكتب. وكيل الترميز هو أمر `grok`.

Hermes Desktop هو ما يجب معرفته، لأن جهازًا لديه Hermes واحد، وهو للتطبيق: يُثبَّت Hermes فقط عبر التطبيق، وأمر `hermes` الذي يُشغّله الوكيل الافتراضي هو للتطبيق. اختيار Hermes كوكيل افتراضي يثبّت نفس ما يثبّته إدخال _تثبيت > AI_: الحزمة، وبيئة تشغيل Hermes تحت `~/.hermes` مُعدّة بواسطة مثبّت Hermes الخاص، الذي يأخذ بضع دقائق في المرة الأولى. بيئة التشغيل تلك هي Hermes الواحدة التي تستخدمها طرفية أمر `hermes` والوكيل الافتراضي والتطبيق، وتحدّث نفسها بـ `hermes update` بدلًا من انتظار إصدار Omarchy. تثبيته يسلّم أيضًا Hermes سمة Omarchy كجلد باسم `omarchy`، الذي يتبعه كل سطح Hermes أثناء تبديلك السمات؛ اختر آخر تحت إعدادات مظهر Hermes أو بـ `/skin` إذا فضّلت عدم فعله، ويترك Omarchy ذلك الاختيار وحده. إزالة التطبيق تحت _إزالة > AI_ تغلق Hermes أولًا، البوابة ضمنًا، وتأخذ بيئة التشغيل تلك معه، وتُبقي محادثاتك وذكرياتك والمهارات التي كتبها Hermes لنفسه ما لم تقل له بخلاف ذلك: يسأل، بإفتراض لا، ما إذا كانت تلك البيانات وإعدادات اتصالك يجب أن تذهب أيضًا.

تجربة OpenClaw لسطح المكتب هي واجهة التحكّم، التي تفتح كتطبيق ويب مدعوم ببوابته المحلية الخاصة. يعيش OpenClaw في `~/.openclaw` ويحدّث نفسه: استخدم زر "Update Gateway" في واجهة التحكّم أو شغّل `openclaw update`، وتعيد البوابة التشغيل على الإصدار الجديد. يختار Omarchy فقط الإصدار الذي يبدأ منه تثبيت جديد. إزالة OpenClaw تحت _إزالة > AI_ تأخذ خدمة البوابة والتطبيق معه ثم تسأل ما إذا كان `~/.openclaw` يجب أن يذهب أيضًا، لأن ذلك يحمل محادثاتك وبيانات اعتمادك جنبًا إلى جنب مع OpenClaw نفسه وبيئات تشغيل المكونات الإضافية التي ينزّلها؛ الافتراضي يُبقيه، وتثبيت OpenClaw مرة أخرى يلتقطه مرة أخرى.

### نماذج LLM محلية

يوصي Omarchy بطريقتين لتشغيل نماذج LLM محلية: LM Studio وOllama. يوفّر LM Studio واجهة GUI للعثور على نماذج وزن مفتوح وتثبيتها وتشغيلها. إنه طريقة رائعة للبدء بسهولة. يقدّم Ollama CLI لفعل ذلك بنفس الشكل. لكن إذا كنت جديدًا على النماذج المحلية، سأبدأ بـ LM Studio. يمكنك تثبيت أيّهما تحت _تثبيت > AI_ في قائمة Omarchy.

### مهارة Omarchy

تساعد مهارات الوكلاء AI على استخدام أدوات محددة بطريقة محددة، ويأتي Omarchy مع مهارة افتراضية لتفصيل النظام. مثل تعديل تكوين Hyprland، أو ضبط الشريط، أو حتى إنشاء سمة جديدة من الصفر. مُرمَّز برابط رمزي إلى دلائل مهارات Claude Code (`~/.claude/skills`) وCodex (`~/.codex/skills`) وPi (`~/.pi/agent/skills`) وAntigravity (`~/.gemini/config/skills`) وHermes (`~/.hermes/skills` وكل `~/.hermes/profiles/*/skills`)، وموقع `~/.agents/skills` العام، بحيث تلتقطه معظم الأحزمة تلقائيًا.

لكن يجب أن تعامل هذه المهارة كتجريبية. ستستخدمها نماذج مختلفة بتأثير مختلف. من الأفضل التشغيل في وضع الخطّة أولًا، بحيث يكون لديك فكرة عما يرغب الوكيل في تغييره. ثم كن مستعدًا لتراجع التغييرات أو حتى استدعاء `omarchy reinstall configs`، إذا أفسد الوكيل كل شيء.
